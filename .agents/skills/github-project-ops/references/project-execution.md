# 進捗と再計画

Issue本文・コメント・担当とPRの実状態を確認し、Projectへ進捗を反映する。既存のStatusが同じ意味を表せるなら再利用する。

## Statusの意味と遷移

| Status      | 判断の根拠                                                                                 |
| ----------- | ------------------------------------------------------------------------------------------ |
| inbox       | 新規流入で、成果や分類をまだ確認していない。                                               |
| triaged     | Priority等の分類を判断したが、開始条件や実施判断が残る。                                   |
| ready       | 受け入れ条件・確認方法が明らかで、未解決の実依存がない。工数・予定日の確定は必須ではない。 |
| in-progress | 実装、調査、Draft PR、レビュー修正などの作業中。                                           |
| in-review   | レビュー可能なPRがあり、レビュー・CI・マージを待っている。                                 |
| blocked     | 作業内では解消できない外部判断や依存により進められない。                                   |
| done        | Issueの成果と必要な検証を満たしたことを確認した。                                          |
| canceled    | 実行しないと判断し、理由をIssueへ記録した。                                                |

- 通常のレビュー・CI・マージ待ちをblockedへ変更しない。修正可能な指摘・CI失敗・競合はin-progressへ戻す。
- 阻害要因が解消したら、実際の再開地点に応じてready、in-progress、in-reviewへ戻す。
- 一時中断では理由と再開条件をIssueに残す。担当の維持・解除はAssigneeで扱い、Statusで代用しない。
- 完了・中止を取り消す場合は再トリアージし、古い完了状態をそのまま流用しない。
- 変更後は対象アイテムと保存したStatusを確認する。自動化で値が戻る場合は、関連ワークフローとIssue/PRの実状態を調べる。

## epicの集約

epicは成果全体を示し、末端Issueと同じ実装候補として数えない。Priorityはepicにも付ける。

1. epic自体の中止が決まっていればcanceled。
2. 必須の子Issueと成果全体の条件を満たしたらdone。中止された子は、不要化や代替が確認できるまで達成扱いにしない。
3. 未完了の成果があり、外部阻害要因がすべての進行を止めている場合だけblocked。
4. 子Issueの実装・レビュー・完了が進んでいればin-progress。
5. 分割・分類済みで未着手ならtriaged、未整理ならinbox。

一部の子がblockedでも、他の必要な作業が進むならepic全体をblockedにしない。

## 次の作業と予定

次の候補はPriorityの高い順を基本とし、期限、後続への影響、実依存、着手可能性を見て選ぶ。高優先度でも依存で進めなければ、依存の解消か次の実行可能な候補を示す。Priorityが未評価なら、候補順を確定する前にトリアージする。

工数は作業量、予定は待ち時間や依存を含む見通しとして分ける。予定は未定・範囲・概算でもよく、進捗に応じて更新する。Milestoneの期限と見通しが合わなければ、範囲・順序・期限の見直し案を示し、日付だけを縮めて間に合うと報告しない。

既存のWIP制限やレビュー・共有環境の制約があれば考慮する。設定のない上限や実行枠を一律に作らず、詳細な容量計算を開始条件にしない。待ちが多い場合は新規着手より詰まりの解消を検討する。

優先度、依存、期限、リスク、見積り、進捗が変わったら、影響する候補と予定を見直す。予定調整を理由に進行中のAssigneeやbranchを変更しない。判断や停止・再開の履歴は `github-issue-pr-ops` のライフサイクルコメントへ残す。
