# フィールドとビュー

## フィールドの保存先

StatusはProjectで管理し、Assignees、Labels、Milestone、関連PRなどはGitHub標準情報を表示する。組織Issue Type・Issue Fieldが同じ意味・型・値域で利用できれば採用してよい。

複数リポジトリのIssueを扱う場合は、全対象で値を読み書きできるか確認する。一部で利用できない組織フィールドを全体の分類として扱わない。必要なら共通のProjectフィールドを使う。既存値を移す場合は対応関係と影響を確認してから変更する。

TypeとIssueラベルの二重管理は許容する。その他のフィールドは保存先を明確にし、同名だからという理由だけで別の意味の値を統合しない。

## 標準の項目

| 項目                             | 用途                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| Title / Assignees / Labels       | Issueの識別、担当、分類。組み込み列を使う。                                        |
| Status                           | 流入・着手・レビュー・停止・完了を示す。意味は進捗運用の資料に従う。               |
| Priority                         | 必須。全管理対象のIssue・epicを優先順位付けする。                                  |
| Type                             | feat、fix、docs、epic、spike等の作業分類。組織Issue Typeやラベルを表示してもよい。 |
| Scope                            | ui、api、db、infra等の変更領域。作業体制は含めない。                               |
| Size / Complexity / Risk         | 変更・レビュー量、設計の未知性、失敗時の影響を区別する。                           |
| Source                           | 問い合わせ、障害、CI、仕様、文書等の流入元。必要な追跡情報を残す。                 |
| Linked pull requests / Reviewers | 関連PRとレビューへの入口。マージ可否はPR自体で判断する。                           |
| Effort / Estimate Confidence     | 概算工数と確度。未定は空欄でよい。                                                 |
| Forecast Start / Forecast End    | 更新可能な予定。計画に必要な場合に使う。                                           |
| Actual Start / Actual End        | 実績を追う場合に使う。確認できない日付を推測で埋めない。                           |

既存Projectでは同義のフィールド・選択肢を再利用する。Priorityの必須性は維持し、他の表示項目や細分化は運用に合わせる。色や名前を揃えるだけのために、既存データを破壊する再作成をしない。

## 標準ビュー

初期設定では次の用途を確認し、既存ビューがあれば再利用する。フィルターは実際のフィールド名・選択肢へ合わせる。

| ビュー           | レイアウトと用途                            | 確認する設定                                                                   |
| ---------------- | ------------------------------------------- | ------------------------------------------------------------------------------ |
| かんばん         | Board。流入、進行、レビュー、停止を見渡す。 | Statusで列分けし、Priorityの高い順に表示。担当と分類を見えるようにする。       |
| WBS/ロードマップ | Roadmap。成果の階層と予定を見渡す。         | 使用する開始・終了日、表示期間、未定項目の扱い。親子関係と依存はIssueで確認。  |
| マージ候補       | Table。レビュー中IssueからPRへ移動する。    | Priority、関連PR、レビュアーを表示。ビュー所属だけでマージ可能と判断しない。   |
| Velocity         | Table等。完了作業と実績を振り返る。         | 完了状態、実績日、採用していれば工数。期間や単位を揃え、親子で二重集計しない。 |

日程や実績を管理しない場合はロードマップ・Velocityを無理に作らない。未定日のIssueがロードマップから漏れても、かんばん等で見つけられるようにする。

Computer Use / Codex Browserで列、並び順、絞り込み、表示フィールド、保存状態を確認する。Priorityはこのスキルの尺度では `p3-critical` が先頭であり、文字列の昇順を重要度順とみなさない。
