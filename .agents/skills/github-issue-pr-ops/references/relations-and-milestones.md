# 親子関係・依存・Milestone

sub-issueは成果を分解するために使う。blocked byは前段Issueの完了まで着手できない場合だけ設定し、自己参照や循環を避ける。Stackのbase順やファイルの重複から依存を自動生成しない。

Milestoneはリリースや締切目標をまとめる必要がある場合に使う。既存の同じ目的のものを再利用し、期限未定なら空欄でよい。見積りや予定日は新しい情報に合わせて更新する。

複数Issueの作成では、親から起票し、返された番号・URLで子Issueと依存を結ぶ。作成結果の識別にタイトルを使わない。依頼済みの起票に追加の確認文字列を要求しない。

関係はGitHub画面からComputer Use / Codex Browserで設定してよい。CLIを使う場合は、インストール済み `gh issue create --help` / `gh issue edit --help` の対応機能を確認する。標準UIやCLIで扱えない場合だけAPIを使う。

変更後は対象Issueの関係を確認する。途中失敗では作成済みIssueを再利用して未完了分を進め、作り直しや自動削除をしない。
