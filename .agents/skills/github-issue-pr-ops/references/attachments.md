# GitHubへの添付

画像、動画、ファイルをIssueやPRの本文・コメントへ添付するときに読む。添付が必要かは[PRの証拠要件](pr-and-merge.md#確認と証拠)で判断する。

## 手順

1. 対象Issue/PRと本文・コメントのどちらへ添付するかを確認する。指定がなければ対象IssueまたはPRの本文へ添付する。
2. ファイルを開き、内容、可読性、秘密情報の混入、サイズを確認する。大きければ [圧縮](compression.md) する。
3. 認証済みGitHub画面をComputer Use / Codex Browserで開き、本文編集欄かコメント欄の標準アップロード機能を使う。利用するブラウザのスキルに従う。Playwrightでファイル選択できる環境ならそれでもよい。
4. アップロード完了を待ち、生成された `user-attachments` URLを保存する。関連する説明の直後へ埋め込み、画像・動画の直下に操作と確認結果の短いキャプションを添えて、依頼された本文更新またはコメント投稿を行う。
5. 投稿後のページを開き直し、画像の表示や動画の再生を確認する。対象のリンクを報告する。

本文をCLIで更新する方が簡単なら、ブラウザで得たURLを使い、最新本文の関連する説明箇所へ挿入して `gh issue edit` / `gh pr edit --body-file` で反映する。更新失敗時は取得済みURLを再利用し、再アップロードを避ける。

認証情報やCookieを抽出せず、内部アップロードAPIを再実装しない。ログイン・権限不足で進めない場合は、必要なユーザー操作を伝える。ローカル保存だけをGitHubへの添付完了と扱わない。

画像・動画だけの見出しや末尾の添付集は作らない。撮ったままの素材でよく、見栄えのためのcut・字幕・zoom・装飾は不要。キャプションは本文のテキストで添え、映像へ焼き込む必要はない。秘密情報の除去と必要な圧縮は行う。画像はGitHubが生成した画像Markdown、動画は生成された添付URLを独立した行に置き、直下に `*保存操作後、一覧に新しい項目が表示される。*` のような説明を書く。
