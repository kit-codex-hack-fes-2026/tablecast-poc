# MCP実演の操作と撮影計画

対象版、商品の変更前後、保存先は[BRIEF.md](BRIEF.md)を正本とする。以下は収録予定であり、実行済みの応答ではない。ChatGPTの接続と公開設定の読取までは確認済み。

## 開始条件

ChatGPTでTableCast stagingを選択し、京料理こもれび四条店だけに接続する。管理画面の商品詳細と同じ商品ID・公開版・説明を `get_configuration` で照合する。競合する未公開下書きがないか管理画面で確認する。下書きや別の管理者の編集が見つかった場合は、そのまま新規収録へ進まない。

録画を開始して開始時刻・テイク名を記録する。ChatGPT、管理画面、客画面の3場面は別テイクでもよい。同じ下書きID・公開版・変更内容の対応は維持する。各操作直前に全体を約2秒見せ、成功結果は下記の時間保持する。応答が遅い場合も原録画を継続し、待機時間の短縮は編集で行う。

## ChatGPTへ渡す入力

> 京料理こもれび四条店の鶏の唐揚げの商品説明を整えてください。対象の商品IDは tablecast-komorebi-karaage です。現在の公開設定を取得し、日本語の説明だけを「鶏もも肉の唐揚げを五個盛りで。衣には小麦粉としょうゆを使用しています。」、英語の説明だけを「Five pieces of fried chicken thigh, coated in wheat flour and soy sauce.」に変更した下書きを作ってください。価格、原材料・アレルギー情報、選択肢、他の商品や設定はすべて保持してください。下書きを検証して差分を確認し、変更がこの二つの説明だけなら公開申請まで進め、店舗名・商品名・変更前後・下書きIDと版・管理画面の確認リンクを簡潔に表示してください。公開の確定は管理画面で私が行います。取得結果が不足して全設定を保持できない場合は、設定を省略して保存せず、その時点で知らせてください。

## 撮影する場面

| 場面ID       | 操作と成立条件                                             | 必ず撮る表示                                                       | 最低保持 | 編集時の要点                                                     |
| ------------ | ---------------------------------------------------------- | ------------------------------------------------------------------ | -------- | ---------------------------------------------------------------- |
| mcp-request  | 上記入力をChatGPTへ送信する                                | TableCast stagingの選択、対象商品名、説明変更の依頼                | 3秒      | 店長の依頼が出発点と分かる範囲を残す                             |
| mcp-draft    | 実際の下書き作成・更新・検証・差分取得・公開申請が成功する | 実行されたツール、対象店と商品、変更案、人による公開確認リンク     | 5秒      | 応答本文だけで成功を判断せず、ツール結果と下書きID・版を照合する |
| mcp-review   | 返却されたstagingのreviewUrlから管理画面へ進む             | 対象店、下書き版、日英説明の変更前後。変更が二箇所だけと分かる差分 | 5秒      | 下書きと公開済みの状態を字幕で混同しない                         |
| mcp-publish  | 店長が差分を確認して公開を確定する                         | 実際の公開操作と成功結果、公開後の版                               | 4秒      | 押下と成功表示の因果関係を残す                                   |
| mcp-customer | 同店舗のお客さま用画面で鶏の唐揚げの詳細を開く             | 商品名、新しい日本語説明、720円。英語へ切り替えて新しい説明も確認  | 各4秒    | 管理画面と同じ商品・説明であることを示す。注文は確定しない       |

ChatGPT側の呼び出しは `get_configuration` → `create_draft` → `update_draft` → `validate_draft` → `get_draft_diff` → `request_publication` を想定する。実行順と結果は実ログで確認し、台本通りだったと捏造しない。`request_publication` の成功を公開完了として扱わない。

DOMの撮影対象と保持計測は各画面の実表示から選ぶ。ChatGPTのUIや管理画面の差分は実収録時に変わり得るため、未確認のselectorやボタン名で自動操作を定義しない。撮影証跡のJSONは実測から保存し、計画値を実測値として書かない。

## 採用判断と再収録

MCPエラー、版競合、変更範囲の逸脱、録画停止、必要文字の欠けがあれば採用を保留する。実際の下書き状態を確認してから再開し、同じ操作の重複で別の下書きを増やさない。価格・安全情報・別商品が変わった差分は公開しない。

採用時は原録画上の入力・結果・保持区間を切り出しへ対応させる。録画していなかった操作を静止画の連続や架空のカーソル操作で実演に見せない。字幕案は、店長が説明変更を依頼、ChatGPTが下書きを作成、店長が差分を確認して公開、卓上メニューへ反映、の4段階とし、実応答に合わせて文言と時刻を確定する。
