# 題材ごとの制作メモ

新しいアプリや大きな変更の制作開始時にこの文書をコピーし、空欄を実装・画面・収録結果から埋める。生成手順はWORKFLOW.md、配置と演出の作例はsample.json／TECHNICAL-DIAGRAMS.mdを参照する。

## 構成と根拠

説明順は「結論 → 見る場所 → 証拠 → 意味 → 次の場面」。商品紹介は一つの利用目的が完了する流れを基本にする。技術紹介は成果、全体構成、重要な処理・状態、検証結果、未検証の点から必要なものを選ぶ。

| 場面の結論 | 実装・テスト・実画面の根拠 | 使う図・画面 | 読み上げる要点 | 注目先と切替 | 実装済み／実測／計画 |
| ---------- | -------------------------- | ------------ | -------------- | ------------ | -------------------- |
|            |                            |              |                |              |                      |

図式は説明する関係に合わせる。主体と通信は構成図、時間順のやり取りはシーケンス図、条件と例外は状態遷移図、検査条件と結果は表、実測比較は軸・単位・条件が明記されたグラフにする。図を画面に入れるために意味を失うほど縮小せず、複数場面へ分ける。未測定値のグラフを作らない。

## 完成品レビュー

対象MP4とreport.jsonを指定して結果を記録する。自動検査の成功を説明・見た目の合格へ読み替えない。

| 確認方法          | 合格条件                                     | 結果・修正点 |
| ----------------- | -------------------------------------------- | ------------ |
| 無音・等速        | 誰の目的か、操作前後で何が変わったか分かる   |              |
| 図を停止          | 主体・関係・条件・出典を読める               |              |
| 音声あり・等速    | 発話と字幕・注目先が一致し、読みや音量が自然 |              |
| 実装と照合        | 実装済み・模式図・実測・計画が区別されている |              |
| 完成MP4と投影環境 | 文字切れ・音切れがなく終端まで再生できる     |              |

再開時はこの制作メモ、入力台本、report.json、採用素材を渡す。過去のチャットやoutput内の一度きりの修正スクリプトを必須手順にしない。
