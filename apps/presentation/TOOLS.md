# 動画基盤で使う技術・スキル

2026-09-13に生成ルートを固定。[GENERATION.md](GENERATION.md) が現行方針の正本、[HANDOFF.md](HANDOFF.md) が到達点。以下の導入調査は履歴を含む。技術紹介v14はHTML/SVGの構成図・シーケンス・状態説明・コード抜粋を採用し、Windowsの最終renderは `--experimental-fast-capture=false` を明示する。

v13追記：OpenScreen CLIのカーソル設定の制約に対し、[実操作カーソルの合成](POINTER.md)だけを既存FFmpegの前処理へ移した。実録・ズーム・編集projectはOpenScreen、全体合成はHyperFrames＋GSAPを継続する。新しい依存やproject形式は追加していない。

2026-09-12、Issue #1の制作環境を棚卸しした。対象は `apps/presentation` の実依存、生成HTML、参照した制作文書とスキル。端末枠を使うか等のデザイン判断と、実行技術の互換性を分けて扱う。

## 確認したこと

- 動画workspaceの描画依存はHyperFrames 0.8.33とGSAP 3.14.2。manifest・ルートlock・インストール済みpackageの版は一致している。生成HTMLはローカルへコピーしたGSAPと `styles.css` を読む。React、Motion、Tailwind、Remotionを動画へ重ねて読み込んでいない。ルートlock内のMotion・TailwindはWebアプリの依存であり、動画用の競合依存ではない。
- 現環境はNode.js 25.0.0、Bun 1.3.13。HyperFramesのNode.js要件は22以上。この組合せでv6の2本を描画済み。全環境・全機能の互換性を保証するものではない。
- リポジトリの `skills-lock.json` にある6件のうち、動画に直接関係するのは `openscreen-demo-video`、実装監査に使うのは `minimum-impl`。デザイン系スキルが多数このlockへ追加された状態ではない。
- `frontend-design@claude-plugins-official` はユーザー設定で `enabled = false`。ローカルキャッシュにSKILL.mdが残っている。v5文書の「適用した」は過去に参照した記録であり、現在の有効化やプロジェクト依存への固定を意味しない。
- HyperFrames 0.8.33の配布物で確認できたSKILL.mdは `hyperframes` と `hyperframes-cli`。そこからCreative/Core/Animate等への参照がある。以前の制作記録にあるCreative/Animationの参照元・版はプロジェクトに十分記録されておらず、同じ内容を再取得できる状態とは扱わない。
- スキル本文は制作時の判断材料であり、生成HTMLが実行するライブラリではない。今回再現した固定幅・固定行高の障害はCSSと生成処理の問題だった。スキル同士のバイナリ互換性が原因という証拠はない。一方、異なる制作方針を選別せず参照する運用上の問題はある。

| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |

| HyperFrames 0.8.33                                          | 映像・音声の時間管理、場面の合成、書き出しを担当                                                                                 |
| GSAP 3.14.2                                                 | HyperFramesが指定時刻へ移動できるアニメーションを担当。別のアニメーションエンジンを重ねない                                      |
| HTML/CSS                                                    | 配置・文字・色を担当。既存 `styles.css` に集約。端末枠は採用技術の要件ではない                                                   |

| frontend-design                                             | 現在は無効。過去の参照記録のみ保持。再び使う場合も文字・余白・情報階層の補助に限定し、Webのhover・スクロール等を動画へ移植しない |
| HyperFrames Creativeなどの演出ガイド                        | 現行方針を決める複数の正本にしない。必要な資料は参照元と版を記録して、具体的な採否を `frame.md` に残す                           |
| imagegen / ComfyUI / 生成動画                               | 必須工程にしない。現行の動画用導入は実画面、技術図はHTML/SVG。必要時の人物なしの補助イラストは選択肢。実装根拠の代用にしない     |
| PowerPoint・Slides用スキル、Sites、Remotion、追加のUIキット | 現行の動画基盤では採用しない。インストールや移行を行わない                                                                       |

## 文書と判断の整理

最新のユーザー指示を優先し、次の文書は役割を分ける。

- `PLAN.md` 冒頭：Issue #1の目的。後半は初期計画の記録。
- `TOOLS.md`：技術・スキルの採用範囲（この文書）。
- `GENERATION.md`：工程と採用判断の正本。`HANDOFF.md`：商品紹介v13・技術紹介v14の保存状態、残件、再開手順。
- `frame.md`：映像設計と過去の制作記録。商品紹介v13はいったん採用、技術紹介v14はレビュー待ち。技術検証をデザインの承認と混同しない。
- `sample.json` / `styles.css` / `scripts`：現在動作する動画の正本。実装済みであることと、デザインが承認済みであることを混同しない。
- `WORKFLOW.md`：現在の再収録・生成コマンド。`LAYOUT.md`：配置の回帰検査と検証範囲。

別のスキルの提案をそのまま追加せず、既存の担当処理と重複しないかを先に判断する。Web向けの自動アニメーションと動画の指定時刻での描画、OpenScreenのズームとHyperFramesのズームを二重に実行しない。デザインの評価はユーザーが行う。

今回の整理ではユーザー共通のプラグイン設定、Webアプリの依存、保存済み素材を変更していない。依存を消すことによる別タスクへの影響を避けるため、プロジェクト内の適用範囲を明記した。
