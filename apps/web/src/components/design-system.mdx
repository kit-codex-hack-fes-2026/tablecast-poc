# TableCastのデザインシステム

店舗や商品を見つけ、状態を読み、次の操作へ進める構造にする。客向けは細い会話欄とメニューの分割、店舗向けは対象の概要と次の操作を先に示す。テーマ編集や注文の構造を、このカタログだけで別の仕組みに置き換えない。

## 色は役割で選ぶ

値の正本は `src/styles.css` の `@theme inline` と `:root`。ここでは値を複製せず、utilityの用途を説明する。

| 意味           | utilityの組合せ                          | 用途                             |
| -------------- | ---------------------------------------- | -------------------------------- |
| 画面           | `bg-background text-foreground`          | 通常の本文                       |
| 内容の面       | `bg-card text-card-foreground`           | 商品・詳細・金額・表             |
| 主操作         | `bg-primary text-primary-foreground`     | Button default                   |
| 補助・選択領域 | `bg-secondary text-secondary-foreground` | 強調し過ぎない内容               |
| 補足           | `text-muted-foreground`                  | 日時・説明。重要な価格を弱めない |
| 情報・進行     | `text-info bg-info-soft`                 | 情報通知・処理状態               |
| 要対応         | `text-warning bg-warning-soft`           | 呼出・会計待ち                   |
| 正常           | `text-success bg-success-soft`           | 確認済み等。状態名も併記         |
| 失敗・破壊操作 | `text-destructive`                       | ErrorNotice、破棄確認            |
| 輪郭・入力     | `border-border` / `border-input`         | 内容区切りと入力を区別           |
| フォーカス     | `ring-ring` と全体の `focus-visible`     | キーボードの現在位置             |

ブランドのアクセントと業務の成否を同じ意味にしない。赤・緑だけで状態を説明しない。透明な面を使っても文字・金額・表には十分な下地を確保する。

## 文字・余白・角丸

本文は標準 `text-base`、補足は `text-sm`。見出しにはPageHeaderを使い、長い日本語・英語で折り返せる `min-w-0` と幅を確保する。重要な文字を画像だけに埋め込まない。

Tailwindの標準スケールを使う。項目内は `gap-2`、同じ対象のまとまりは `gap-4` / `space-y-4`、対象間は `gap-6` / `space-y-6` を基本に、密度に応じて選ぶ。これらは新しいトークンではなく配置上の目安。角丸は `rounded-lg` / `rounded-xl` を使い、値を別の表に転記しない。

通常のButtonは48px以上、コンパクトなButtonも44px以上、卓上の主操作は `size="lg"` で56px以上。長いラベルは高さを伸ばす。Checkbox/Radioはラベル全体を44px以上にする。状態表示のBadgeをボタンの代わりに使わない。

## 動きと操作

押下・色変化はCSSの150ms程度、状態の入退場は既存MotionProviderとActionFeedbackを利用する。操作を待たせない。表の数値や行を装飾目的で動かさない。`prefers-reduced-motion` はCSSの `motion-reduce` とMotionの `reducedMotion="user"` で尊重する。MotionProviderはアプリとStorybookの入口に置き、featureごとに増やさない。

音声の停止・接続状態は既存の視覚表示と操作で伝える。状態をAgentに読み上げさせる処理は追加しない。スクリーンリーダー向けのラベル・statusは別のアクセシビリティ上の責務として維持する。

## 初見・キーボード・日英

- 商品名・店舗名・来店など、対象名を詳細への主リンクにする。行全体のクリックやリンク内ボタンを避ける。
- inputにはlabel、アイコンだけのボタンにはaria-labelを付ける。placeholderをラベルにしない。
- DialogにはTitleとDescription、閉じる操作、開いた元へのフォーカス復帰を用意する。
- 失敗時に入力や取得済み内容を消さず、ErrorNoticeで原因と再試行を示す。0件、読込中、失敗を区別する。
- ツールバーの言語切替で日英を確認する。英語はイギリス英語。390px、iPad縦横、200%拡大、Tab・Shift+Tab・Enter・Escape・矢印キーで操作する。
- a11y自動検査の成功と、スクリーンリーダーや実端末の確認は別に報告する。

## 部品の境界

`components/ui` は業務非依存の操作・表示、`components` はフォーム・翻訳・状態等の共通表示、`features` は業務の状態と操作を所有する。金額・権限・注文確定はAPIの判断を使う。

各部品のDocsで用途・props・StoryのSourceを確認する。NativeSelectとSelect、TableとDataTable、FieldErrorsとErrorNoticeなど、似ていても責務が違うものを置き換えない。

## 対象を形で見分ける

人物はUserIdentityの丸い画像・人物アイコンと名前・メールを一組にし、長いメールも折り返す。客向け同席者はParticipantIdentityを使い、共有を許可した名前だけを表示する。内部ID・短縮ハッシュを表示名へ代用しない。

卓は卓名と来店、伝票状の金額、独立した詳細ボタンをまとめる。公開履歴は縦の公開版と派生する下書きで関係を補助する。静的な内容の面をボタンのように浮かせず、実行にはButton、移動には下線付きリンクを使う。状態のBadge自体は押せない。

DateTimeとcalendarDateは年・月・日・曜日を言語に自然な形で表示する。JSTやハイフン区切りを表示へ足さない。Dialogとdrawerのoverlayは暗幕だけにし、背景をblurしない。

## 原色から意味、意味から操作状態へ

`@radix-ui/colors` のスケールを `styles.css` で読み、TSXは意味別のutilityだけを参照する。Grayを標準とし、原色名・hex値・黒1pxの境界を画面側へ直書きしない。店舗独自色は既存の店舗テーマ境界だけで扱う。

| スケール | 意味別の使い方                                                           |
| -------- | ------------------------------------------------------------------------ |
| 1–2      | background、muted。静的な背景                                            |
| 3–5      | control、control-hover、control-selected。操作と選択                     |
| 6–8      | border、control-edge、control-edge-hover。区切りと操作境界               |
| 9–10     | success-solid等の役割別の塗りとhover                                     |
| 11–12    | muted-foreground、foreground、役割別の文字。実背景とのコントラストを検査 |

主操作はprimaryのチャコール。一般的な選択・リンク・人物を青にしない。成功・注意・危険・情報の色はhover・選択・focusまで同じ役割を維持する。状態ラベルは実背景上のコントラストを保証するため12を使う。ナビゲーションの色は群見出しと現在項目に限定し、群内の未選択アイコンは文字色に従う。

## 光・影・操作面

Buttonは上辺の光、浅いグラデーション、接地する影を持ち、押下時は沈む。Inputは内側の浅い陰影、静的カードは抑えたsurface shadow、Badgeは平らな状態面を使う。ガラスはshell・浮いた操作面へ限定する。影や色だけを操作性・focusの唯一の手掛かりにしない。

通常48px・compact44px・客向け主操作56pxをButtonとInputで共有する。Badgeは内容に合わせて伸びる静的表示。クリック用途へ流用せず、Buttonまたはlinkを使う。tableの見出しとセルは共通余白、数値は右揃え・等幅数字、対象名は左揃え。

NativeSelectとSelectは末尾に独立した矢印領域を確保する。選択値が長くても矢印を押し出さない。LanguageLabelの国旗は18×14pxの補助表示で、言語名を残す。言語ごとの編集はLanguageFieldsで一つの対象にまとめ、列を増やさない。非表示の言語の入力も保存・validationの対象に保つ。

## 対象の近くに必要な操作を置く

説明だけのAccordion・details・Popoverを作らない。短い補足は対象のlabelや操作へ隣接させる。実データ、編集項目、ナビゲーションの開閉は用途と内容が判別できる場合に使う。

設定対象はshellの公開版・下書き・履歴の切替で一貫させる。入力はfeatureが所有し、共通headerへ保存状態と操作だけを描画する。保存失敗・409・再取得失敗で入力を消さない。現在のオブジェクトが切替先にない場合はその一覧へ戻す。公開選択だけで公開内容を変えない。

## 再発を検出する境界

見た目の正本は共通部品とこのカタログ。画面でサイズ・色を上書きする前に既存variantを選ぶ。必要な状態が不足した場合は共通variantとStoryを同じ差分で追加する。

- 既存Tailwind lint：原色スケール・純黒/白のutility・arbitrary colorをerrorにし、semantic tokenへ誘導する。
- `design-system.browser.test.tsx`：操作面の不透明度、状態色hover、focus、48px、矢印の位置、国旗寸法、390pxの横溢れ。
- `admin-shell.browser.test.tsx`：人物選択を開閉した座標、sidebarの群・幅・店舗と組織の保持。
- `configuration-workflow.browser.test.tsx`：未保存保護、保存・409・再取得失敗、権限、店舗切替。
- `configuration-editor.browser.test.tsx`：言語を列に増やさず390pxで編集・validationできること。
- カメラ・kioskのBrowser：許可待ち中のOFF、遅延stream解放、非表示、縦横の幅復元、注文と音声状態の保持。
- Storybookのa11y：役割色のコントラスト、見出し順、名前とfocus。静止画は質感と配置、操作動画は状態遷移の証拠として併用する。
