# 製品の価値と検証経路

TableCastは、食べたいものを相談する客、確認を受けるスタッフ、接客を準備する店長を、一つの店舗設定と注文状態でつなぐ。LPは困りごとと実画面を、READMEはその体験を支える実装と検証の入口を示す。

## 利用ケースと実装

| 場面                                             | 利用者が得る価値                                       | 実行する入口                                        | 裏付け                                                                                           |
| ------------------------------------------------ | ------------------------------------------------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 刺身に合う辛口の地酒を少量ずつ選ぶ               | 銘柄を知らなくても好み・量・価格から相談できる         | 卓上の音声と商品画面                                | [音声の業務操作](voice/integration.md)、[メニュー設定](product.md)                               |
| 海外のグループが食べ方や豚肉・調味料について聞く | 母語で質問し、不明点を厨房へつなげられる               | 多言語の料理情報とスタッフ呼出し                    | [食材情報](product.md#アレルゲンと食事制限)、[呼出し](ui.md#店員への用件相談と呼び出し履歴)      |
| 年配の客が温かいお茶と少量の料理を頼む           | 声とタッチを行き来し、自分のペースで選べる             | 同じカートを使う音声・GUI                           | [注文操作](product.md#共通の注文操作)、[UI](ui.md)                                               |
| 営業の合間にお品書きと写真から設定する           | 商品・翻訳・接客文の入力をまとめて進められる           | Agent Plugin → MCP → 下書き → 人の公開承認          | [実行可能な依頼例](../plugins/tablecast/skills/tablecast/references/use-cases.md)、[MCP](mcp.md) |
| スタッフが調味料の確認に向かう                   | 原文・要約・案内済み内容・未解決点を把握して対応できる | 卓上の呼出し → 管理画面の引き継ぎメモ               | [スタッフ対応](ui.md#店員への用件相談と呼び出し履歴)                                             |
| 店長が営業後にメニューを改善する                 | 集計の根拠から具体的な説明文や接客の変更へ進める       | get_statistics → get_configuration → 採用案の下書き | [統計](statistics.md)、[分析skill](../plugins/tablecast/skills/tablecast-analytics/SKILL.md)     |
| 次の来店へつなげる                               | 会員証・来店記録・ポイント・クーポンを持ち歩ける       | 本人の会員アプリと店舗別の同意・記憶                | [会員](membership.md)                                                                            |

音声モデルが作る説明と、店舗が確認した食材情報は別である。宗教上の適合性やアレルギーの安全を未知の情報から保証しない。LPの観光客の場面は、必要な確認をスタッフへつなぐケースとして示す。

## 審査で伝える焦点

| 観点       | 見せる内容                                                                                                       | 確認できる成果物                                                            |
| ---------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 作品の価値 | 言葉や操作の壁を下げ、店員の対応を文脈ごと引き継ぐ。導入から営業後の改善まで店の仕事をつなぐ                     | LPの5場面と実画面、Pluginの資料取込・改善・分析の依頼例                     |
| 完成度     | 注文・店舗管理・会員の3つの入口、音声停止後も残るカート、下書きと公開の分離、多言語、実際の端末接続              | WebのStorybook・Browserテストと代表E2E、PR添付のPC・スマートフォン表示      |
| 技術レベル | WebRTC音声とResponses delegation、GUI・音声・MCPの共通業務処理、版付き確認、店舗・卓の認可、D1の永続状態とDO通知 | READMEの構成図、APIの実Binding・MCP transportテスト、仕様から実装へのリンク |

機能があること、テストが通ること、実店舗で効果が出たことを混同しない。導入時間や売上の改善率は計測値がない限り掲載しない。

## 依頼例を検証する方法

[Pluginの依頼例](../plugins/tablecast/skills/tablecast/references/use-cases.md)を、実際の[MCP登録](../apps/api/src/modules/mcp/routes.ts)と[tool schema](../apps/api/src/modules/mcp/configuration-tools.ts)へ照合する。資料のOCR・画像生成はクライアント機能、設定保存・検証はMCP、公開は人の管理sessionが担当する。公開pluginの接続先と、画面に表示する現在のoriginの接続先を区別する。

既存のテストで次の実行境界を確認する。自然言語の理解と計画は含まないため、実モデルによる依頼完遂・翻訳品質・実端末の音声品質は別の受入とする。

- [mcp-configuration.test.ts](../apps/api/test/mcp-configuration.test.ts)：実MCP clientで設定取得・画像取込・多言語下書き・検証・公開申請を実行し、人のsessionと対象版なしの公開を拒否する。
- [mcp-food.test.ts](../apps/api/test/mcp-food.test.ts)：食材分類・具材の増減・根拠の保存を往復する。
- [mcp.test.ts](../apps/api/test/mcp.test.ts)：OAuth・scope・店舗境界・接続取消を確認する。
- [statistics.test.ts](../apps/api/test/statistics.test.ts)：実D1で期間・母数・ページング・権限と集計の往復を確認する。

実行結果と対象SHAはPRへ記録する。写真は利用場面を伝える生成素材、画面は隔離されたアプリfixtureのスクリーンショットである。制作の出所は[LP素材](../apps/web/public/landing/README.md)へ残し、生成写真を導入店舗の実績として扱わない。

## LPの参考構成

[Studio](https://studio.design/ja)の制作物を見せる構成、[kintone](https://kintone.cybozu.co.jp/)の用途から機能へ進む構成、[SmartHR](https://smarthr.jp/)の利用者と業務課題を結ぶ説明、[LayerXのバクラク](https://bakuraku.jp/)の業務をつなぐ価値の伝え方を参考にする。TableCastでは主CTAを店舗管理に置き、3つの実アプリ、利用場面、初期設定、営業後の改善を既存の色・書体・共通部品で示す。他社の導入実績・数値・認証や配色を転用しない。
