# 接客方針のMarkdown編集

[Issue #359](https://github.com/kit-codex-hack-fes-2026/tablecast-poc/issues/359) · [初期互換設計 #177](https://github.com/kit-codex-hack-fes-2026/tablecast-poc/issues/177) · [UI仕様](ui.md) · [MCP契約](mcp.md)

## 編集と表示

接客方針はMarkdownを直接編集する。SKILL.mdなどの文章を記号・空行・末尾改行を保って貼り付け、同じ場所のプレビューで書式を確認できる。WYSIWYG、スラッシュコマンド、独自の文書エンジンは設けない。textareaは内容に合わせて伸び、利用者も縦方向にリサイズできる。入力のUndo/Redoはブラウザー標準を使う。プレビューへの切替でtextareaを作り直さない。

言語はAPIの `localeSchema.options` に基づくBase UI Tabsから選ぶ。1言語を画面幅いっぱいに表示し、非表示言語の入力と編集履歴は保持する。非表示言語に必須項目のエラーがある場合は該当タブを開いて入力へ移る。接客方針と話す声を言語ごとにまとめ、自発的な声かけは言語共通の設定として外に置く。

新しい文字列のプレビューは既存Streamdownを静的表示に使う。HTMLを実行せず、画像を取得しない。リンクも本文として表示する。既存の構造化文書はReactで許可ノードを描画し、その形式のまま読める。公開概要にも同じ描画を使用し、固定行数で本文を切り捨てない。

## 保存と旧データの保持

`cast.instructions` は従来どおり文字列、または次の版付き文書を受け取る。API schema、DB schema、互換headerは変更しない。

```json
{
  "format": "tiptap-json",
  "version": 1,
  "document": {
    "type": "doc",
    "content": [{ "type": "paragraph", "content": [{ "type": "text", "text": "丁寧に案内する" }] }]
  }
}
```

APIの `instruction-model.ts` が許可schemaと `instructionText` を所有する。文字列はそのまま、文書は見出し・リスト・強調・改行・literal文字を含む文字列へ決定的に投影する。Webはこの共有関数を入力表示と文字数の確認に使う。LiveとResponses delegationにも同じ投影を渡す。

読込・focus・言語切替・プレビューだけではdirtyにせず、構造化文書を元の値のまま保持する。利用者が本文を編集した言語だけをMarkdown文字列に変更する。元の投影へUndoした場合は元の構造化値へ戻す。他言語のデータを書き換えない。明示保存まではAPIへ送信しない。

上限は5,000 UTF-16単位で、書式記号と改行を含む。上限を超えても入力は切り捨てず、欄の近くにエラーを示して保存を止める。APIも同じ上限を検証する。旧構造化データに対するリスト深さ・走査量などの既存制限は維持する。

正本は既存フォームが所有するConfigurationとし、本文の複製を保存しない。D1の既存 `config_json` を使用し、列追加や移行SQLは不要。差分は従来どおり言語ごとに1項目として扱う。

## 互換通信と保存フロー

HTTPの `X-Tablecast-Instructions: 1` は維持する。文書を読めるクライアントへ元の文書を返し、旧クライアントには投影した文字列を返す。下書き・公開catalog・卓・デモを同じ規則で扱う。

Webは保存時の `instructionFormatVersion: 1` を引き続き送る。省略した旧クライアントによる既存文書の上書きは409 `DRAFT_CONFLICT` とする既存契約を維持する。文書が保存された後に文書を読めない旧APIへ戻さない。

保存成功・再読込・入力を戻す操作は既存featureが所有する。保存待機・読取専用時は入力をdisabledにする。503・409では両言語の未保存内容を保持する。概要からの編集は言語を選択し、指定された接客方針・声・声かけへ一度だけfocusを移す。保存や入力を戻す操作で初回focusを繰り返さない。

## 検証境界

- APIの既存unit・D1テストは、旧文字列・構造化文書・本文投影・文字数・互換応答・上書き拒否・公開を保証する。
- Browserは、読込での無変更、Markdownの記号と空行、プレビュー、Undo、縦方向の伸縮、上限超過の保持、disabled、非表示言語の入力エラー、503・409後の入力保持、概要からのfocusを確認する。
- Storybookは、言語別の音声候補と本文の保持、候補の追加取得失敗と再試行、店舗切替後に旧候補を残さないことを確認する。
- 既存のSSR・認証・公開E2Eを維持する。UIの反復操作だけを理由に全構成E2Eを追加しない。

実行結果・対象SHA・画像はPRへ記録する。自動ブラウザ試験を実iPadの日本語IME・VoiceOver確認の代わりとは扱わない。
