# Agent Plugin用のseed

[Seedの正本](../demo.md) / [pluginの使い方](../codex-plugin.md)

## 想定依頼とデータ

標準の`demo`と`history`は、3店舗へ次の架空データを投入する。`smoke`は従来の最小データを保つ。ゲームは追加しない。

| 依頼例                                             | seedの根拠・確認先                                                                                                                                                                        |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026年10月の売上と人気商品ランキングを分析して     | 各店に9月40組・10月60組の閉卓済み来店。注文は各4件で合計1,200件。会計・人数・プラン・選択肢・取消・会計訂正・呼出も含む。`get_statistics`で月ごとのsummary、products、modifiersを取得する |
| 売切商品を一覧表示して、メニューの改善案を提案して | 公開カタログの`available=false`。こもれびのほっけ、ハヌルの栗マッコリ、Westwardのスタウト。履歴は売切期間を推測する根拠にはしない                                                         |
| 外国人観光客向けに料理の英語説明を改善して         | 全102商品の4言語の意味訳・転写・説明、数量・生食・調味料・必須選択・税込価格、全商品・具材の確認済み食事情報。国籍や観光目的を会員名から推測しない                                        |
| 来店3回以上の会員向けクーポンを企画して            | 各店12会員。確認済み来店0〜10回、購入額配分と10ポイント/来店の履歴。退会済み1名。来店3回以上の有効会員は7名                                                                               |
| 既存特典と配布対象を確認して                       | 来店3回で500円引き、来店3回かつ購入額配分30,000円以上で10%引き、50ポイント交換、手動発行の4ルール。来店3回特典1枚と手動券1枚を発行済み                                                    |

月次履歴は`scripts/tablecast-seed/analytics.ts`、会員・特典は`rewards.ts`が正本である。来店IDの`-plugin-history-`、会員ユーザーIDの`tablecast-plugin-customer-`、eventの`synthetic-history`が投入元を示す。会員メールは予約済みの`.invalid`ドメインを使う。会員の個人記憶、共有・保存の同意を作らない。

9月・10月とも1〜30日の17時以降（日本時間）へ分散する。10月31日は初期整備時点で進行中のため固定月次履歴を置かない。既存の実行・手動操作による来店も統計へ加わるので、stagingの値は固定seedだけの集計より増える場合がある。実店舗の売上・需要・施策効果とは扱わない。

来店3回ルールをそのまま`preview_coupon_audience`へ渡すと、初期状態は有効会員11名、発行対象6名・既発行1名・条件外4名になる。新しいルール案として`ruleId`を省略すれば7名が対象になる。企画・対象確認と保存・発行は区別する。ポイント・会員の利用状態・既発行券は再seedで巻き戻さない。

## 既存stagingへ反映する

通常配備は既存設定を上書きしない。[staging seedの明示更新](../deployment.md#staging-seedの商品情報と営業データを更新する)を実行する。seedの既存102商品について説明・食事情報・対応する選択肢の成分変更を更新し、商品名・価格・販売状態・追加商品・音声設定・認証・端末・過去注文・未公開下書きを保つ。公開版を進め、未送信の注文確認は失効する。客画面を再読込みして反映を確認する。店側デモは元の設定版を保持するため、必要なら管理画面の再読込み操作で取り込む。

月次履歴、会員、ポイント、発行ルールと券は固定IDで追加する。再実行は既存行を更新しない。更新失敗時は同じ手順で未投入分を再開する。seedの説明・食事情報を手動編集していた場合、その部分は今回のseed定義へ揃う。

## API・サーバー改修が必要な不足

今回の変更はseed・運用script・文書に限定し、次のAPIの制約は変更しない。

- 統計応答には合成履歴だけを識別・除外するフィールドがない。利用時にstagingとseed由来であることを示す必要がある。
- 商品統計は数量・注文した来店数・注文率であり、商品別の実売上金額や粗利益ランキング、原価、売切期間、国籍・観光目的は取得できない。
- 会員検索MCPはIDと表示名だけを返す。会員ごとの累計来店・購入額を列挙するtoolはなく、条件に合う人数は`preview_coupon_audience`で確認する。
- 模擬Googleログインの選択肢は既存の共通名簿に限る。追加した分析用会員36名の個人画面へのログイン導線は追加しない。

これらはseedを増やして実装済みに見せない。質問の頻出傾向・実決済や外部POSの情報も作らない。
