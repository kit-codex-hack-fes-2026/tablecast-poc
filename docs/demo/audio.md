# デモの合成音声素材

[デモ資料](README.md) / [台本と個別試聴](dialogue.md) / [機械可読台本](dialogue.json) / [声のペルソナ](personas.md) / [実有料E2Eチェックリスト](paid-e2e-checklist.md)

## 素材の目的と保存先

客の複数の声・アクセント・数量訂正を、同じ入力で繰り返し確認できるようにする。Inworld TTSで人物別の発話を作る。全員が架空の成人であり、実在人物の声を複製しない。生成できたことと、実聴で設計意図を満たすことは分けて記録する。

台本は8シナリオ・52の客発話を持つ。客の音声は個別MP3、重なりは該当2発話を合わせた48kHz・mono WAVとして[assets/demo/audio](../../assets/demo/audio/)へ保存する。入力文は[dialogue.json](dialogue.json)、実voice設定は[voices.json](voices.json)、出力ファイル・SHA-256・生成条件・実長は[音声manifest](../../assets/demo/audio/manifest.json)を正本にする。生成方法は[tablecast-demo-audio.ts](../../scripts/tablecast-demo-audio.ts)を参照する。ファイルがないものや失敗したものを生成済みと表示しない。

## 生成と再利用

`ffmpeg`と`ffprobe`をPATHへ置き、rootの標準envファイルに`INWORLD_API_KEY`を用意する。鍵はmanifestやログへ出力しない。依存追加はなく、Bun・Inworldの公式HTTP API・ローカルFFmpegを使う。

```sh
# 生成予定だけを表示する。API呼出しなし。
bun run demo:audio

# 明示したときだけ有料TTSを呼ぶ。生成済み素材はSHA照合して再利用する。
bun --env-file=.env.local run demo:audio --generate

# 台本・声の指定・音声ファイルのSHAと、音声の実長・形式をローカル検査する。
bun run demo:audio --verify
```

`--only dietary-02`のように発話IDを付けると1発話だけを生成できる。モデルは`inworld-tts-2`、48kHz・128kbpsのMP3、`deliveryMode: STABLE`を使う。[公式合成API](https://docs.inworld.ai/api-reference/ttsAPI/texttospeech/synthesize-speech)の`voiceId`・`language`・`instruction`・`speakingRate`を各話者へ指定する。APIエラーは自動再試行しない。成功レスポンスは音声検査前に保存し、検査中断後も取得済みレスポンスから再開する。

台本または声の設定を変えて`--generate`すると、変更した発話だけが新しい有料合成の対象になる。変更していない音声とローカル混合は再利用する。SHAが記録と異なる手編集ファイルは自動上書きしない。API応答前の通信中断では生成完了の有無を判断できないため、再実行前にInworld側の利用記録を確認する。

## 客入力と店員の参考音声

| 区分           | 台本の位置                                 | 用途                                         | 生音声E2Eへの入力                                                                    |
| -------------- | ------------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------------------------ |
| 客入力         | `scenarios[].turns[]`                      | マイク/検証用入力経路へ流す個別発話          | 指定のcueと実際の状態に従って入力する                                                |
| 客の重なり     | `overlap_previous`のturnと直前客turn       | 2人の同時発話を再現する混合クリップ          | 元の2本を別々に再生した上でさらに混合版を再生しない。該当区間を混合版1回に置き換える |
| AI店員の演出例 | `staffExamples[]`、`usage: reference_only` | 接客の雰囲気を試聴・説明する参考素材3本      | 入力禁止。本物のAI応答や専用確認の代わりに流さない                                   |
| 本物のAI応答   | 実行した製品のRealtime・業務tool・TTS      | 応答の意味・業務状態・音声品質を評価する出力 | 客入力へloopbackしない。音響回り込み条件は別途記録する                               |

店員例文を含めた全編の固定音声を、成功する会話としてE2Eへ自動投入しない。実応答と状態を待つ。映像の演出で参考音声を使う場合は、参考音声であることを示し、実動作証拠と混ぜない。

## cueの基準

| type                   | 再生の基準                                                                  | offsetMs                                                          |
| ---------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `after_previous`       | 最初の発話、または直前の客クリップと記載されたGUI操作・接続条件が完了した後 | 指定時は前提成立後の待ち時間。固定時間で接続完了を推定しない      |
| `after_live_response`  | 直前に実際に生成された店員TTSの再生完了と、記載された業務状態の確認後       | 原則不要。承認では現行確認の全文読了を待つ                        |
| `overlap_previous`     | 直前の客クリップが始まった時点                                              | その開始から2人目が入り始めるまでの非負ms。今回は250msまたは300ms |
| `during_live_response` | 本物の店員TTSが実際に聞こえ始めた時点                                       | その開始から割り込み客音声までの非負ms。今回は400〜600ms          |

`overlap_previous`のオフセットが先行clipの実長より短いことを確認する。`during_live_response`も実応答が終わる前に挿入できたかを音声・時刻で確認する。想定した開始時刻だけをログへ書かない。該当の実応答が短くて割り込めなければ、割り込み条件が成立しなかったと記録する。

## 音声だけでは表せない操作

`ja-stop-resume`では、既注文フライ580円を正規のGUI承認で準備し、バーガーへのチェダー追加がcommitした後にGUIで音声を停止する。`stop-03`は停止中に入力側で再生し、capture・送音・認識・生成・業務更新が発生しないことを確認する。その後GUIで明示再開し、実接続完了後に`stop-04`を流す。STOP/再開ボタンの操作を、客の音声命令で代用しない。

`ja-confirmation-reapproval`では、実際の専用確認Aの読み上げ中に訂正を入れる。新しい確認Bの内容・版・全文読了を確認してから最後の承認を入力する。古い確認を承認するタイミングを固定音声の無音区間だけで作らない。

## 実聴の記録

| 観点             | 記録すること                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 自然さ・明瞭さ   | 不自然な抑揚、過度な演技、歪み、無音、途切れの有無                                             |
| 読み             | 月凪・雪灯・ぬる燗・サムギョプサル・マッコリ、セット数・本数・器の人数、円と容量が意図どおりか |
| 声の区別         | 同じ卓の客どうしで聞き分けやすいか。本人識別の実装を保証するものではない                       |
| 年齢・性別の演出 | 設計した印象に近いかという主観所見。実年齢・性別の推定として扱わない                           |
| 英語のアクセント | US/UK/India/Chinaの設計意図に近いか、明瞭で誇張されていないか。未確認なら未確認と記録          |
| 重なり           | 対象2声が実際に重なり、音割れせず、オフセットと実長がmanifestに記録されるか                    |

有料TTS素材の生成結果、実聴結果、実有料E2Eの結果は別の記録である。この資料と台本の追加だけで実E2Eを実行したことにはしない。実行時の記入欄は[応答チェックリスト](paid-e2e-checklist.md)を使う。
