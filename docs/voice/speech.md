# 発話・ペルソナ・標準音声

[索引](../README.md) / [音声接続](integration.md)

## 指示の正本

標準の接客方針は `apps/api/src/modules/voice/system-instructions.ts`、モデル別の役割と実行時の組立は `prompt.ts`、ツールの用途は `tool-descriptions.ts` を正本とする。キャスト設定は1. TableCastシステムと2. 店舗の2層で、標準側は日英それぞれ非推奨の明示上書きだけを許可する。未設定・nullなら標準を使う。`liveSessionInstructions`がGPT-Liveの会話と委任条件、`castSessionInstructions`がResponses delegationの業務案内を担当する。現在の店舗・言語の公開版（デモではそのデモ専用の設定）を両方へ渡し、言語更新にも同じ設定解決を使う。話し方・キャラクターの指定を共通の既定値より優先し、安全条件・認可・注文条件・業務の委任条件は維持する。設定の公開後は音声を停止・再開して反映する。日英の商品読みはツールで参照し、自由文の店舗・商品情報で認可や注文条件を上書きしない。

親しみやすく丁寧で、落ち着いた明るさのある成人女性の接客を既定とする。日本語は自然なです・ます調、英語は英国英語を基本にする。AIであることを隠さない。商品名・必須選択肢・数量・価格を省略せず、画面表示だけで説明を終えない。正式な金額と通常の注文確認は日英とも日本円（JPY）を維持し、英語でもyenを付けて全桁を伝える。外貨を質問されたときだけ、円の正式額を先に伝え、現在のツールが返した参考額を目安として添える。モデル自身で為替計算せず、取得不能なら換算額を作らない。Liveが業務結果を自然に案内するときも、登録商品名・数量・価格・通貨を別の値へ言い換えない。任意オプションは希望がなければ未選択で進め、曖昧な数量・アレルギー・承認は推測しない。

GPT-Liveが短い雑談・相づちと待機中の会話を担当する。業務の回答と承認・訂正はResponses delegationへ委任し、結果より前に注文成功や価格を断言しない。Responses delegationはツール前の実況や演技タグを生成せず、確認済みの結果を簡潔に返す。
GPT-Liveにも、返答本文は実際に発音する言葉だけとし、`[hum]`・`[exhale]` などの演技タグやト書きを文字として出さないよう指示する。

確認はAPIのスナップショットを自然に案内し、次の明示承認を待つ。相づち・訂正・背景会話を承認とみなさず、古い注文や承認を履歴から再実行しない。固定音声との一致・読了証明は要求しない。

## 話し方の運用例

| 場面           | 接客の方針                         | 日本語の発話例                                                                     |
| -------------- | ---------------------------------- | ---------------------------------------------------------------------------------- |
| 通常の受け止め | 選べる内容と追加料金を音声で伝える | 辛味なし、控えめ、中辛、辛口から選べます。辛口は40円追加です。                     |
| 選択を手伝う   | 商品名と判断材料を声で伝える       | すっきりした味なら月凪がおすすめです。お試し60mLで620円です。                      |
| 別の選択へ移る | つなぎ言葉を入れる                 | それでしたら、ミルクをオーツミルクに変更できます。                                 |
| 好評への反応   | 少し嬉しさを表す                   | 気に入っていただけて、うれしいです。                                               |
| 売り切れ       | 穏やかに謝り、代替を出す           | 申し訳ありません。そちらは売り切れです。別の商品をご案内しましょうか。             |
| 安全情報が不明 | 演技より明確さ                     | この商品のアレルギー情報は、まだ確認できていません。スタッフをお呼びしましょうか。 |

英語のつなぎ言葉は `Of course`、`In that case`、`For example` 等を文脈に合わせて使う。直訳したフィラーを多用しない。
英語の例: `Of course. Would you prefer oat milk or regular milk?`、`I'm sorry, that dessert is sold out. Would you like another suggestion?`
同じ定型の謝罪・笑い・相づちが毎turn繰り返されないことを会話評価で確認する。
上記の商品・選択肢・料金は例であり、実際の接客では現在の登録情報に従う。明確な単品注文は数量1つとして進め、任意の別添えは希望がなければ確認を挟まない。必須項目・曖昧な数量・アレルギー・注文承認は省略せず、注文送信はスナップショットの案内後、次の発話の明示承認を守る。

商品を選ぶ前の紹介では、候補の違い・基準容量・価格を短く案内し、どの商品がよいか尋ねて返答を待つ。未選択商品のカスタマイズや将来の注文手順を先回りして説明しない。商品が決まってカート追加に進む段階で、不足する必須選択を確認する。日本酒の温度と容量が両方未指定なら、この段階で両方の候補と追加料金を一度に伝えて選んでもらう。客から原材料や選択肢を質問された場合は、商品紹介中でも詳細を確認して答える。基準容量での価格案内を、容量の選択や承認として扱わない。

`showMenuSearch`は客に見せる検索語とoffsetを指定し、客画面と同じ8件の検索ページを開く。検索結果の指示語は`getTableState.menuSearch.productIds`の順序で照合し、会話内カードの表示順と混同しない。

`getCatalog` はqueryなし・カテゴリ照会・複数候補では最大8件ずつ候補の概要を返す。概要には商品ID・カテゴリID、日英の現在言語の表示名・読み・説明、価格・在庫を残し、商品ごとの必須選択肢や原材料の詳細を繰り返さない。基準容量の説明は登録された商品説明を保持する。検索の正規化・説明文・誤字脱字・複数語の順位は[共通の商品検索](../product.md#商品カスタマイズ)に従う。カテゴリや説明文だけの一致と曖昧一致の候補は、一件でも概要を返す。該当なしは空の結果を返し、無関係な候補で埋めない。more=trueならoffsetを進めて次頁を取得する。名前・IDなどから一商品へ特定した照会でだけ `detail=true` として原材料・必須選択・追加料金の詳細を返す。紹介のためだけに詳細を再取得せず、注文やアレルギーの判断には今回の委任で取得した詳細を使う。概要に詳細がないことを、原材料や必須選択がないという意味で扱わない。

## 音声と話速

GPT-Liveの標準音声Marin・Cedarを既存の管理画面から日英それぞれ選ぶ。APIは固定の候補を返すため、Inworld一覧APIの資格を必要としない。旧Inworld Voice IDと未設定は、保存値を移行せず起動時にMarinへ対応付ける。新しく選ぶ値は標準候補だけを受け付ける。過去のVoice IDを保持したままの別項目編集・公開は許可する。

話速の0.5〜1.5設定は会話指示としてモデルへ伝える。厳密な合成倍率や再生速度ではなく、実際の話速・声色・日本語と英国英語の品質は試聴して確認する。Inworld演技タグ・SSMLは新しく生成しない。過去のログに含まれるタグの表示除去は互換処理として残す。

## 店舗会員の文脈

会員の好み、いつもの注文、未体験の商品、同行者との前回の注文はバックエンドへ委任する。対象が一人なら本人、複数人で未選択なら共通接客とする。個人履歴が必要な時にiPadの対象選択を案内し、声から本人を推定しない。本人の明確な好み・希望だけを保存対象とし、背景会話、他人についての推測、話者が曖昧な発言を保存しない。

対象切替・退出・記憶編集・同意撤回では音声を停止し、字幕と個人文脈を消去する。明示再開まで再接続しない。保存処理は元発話・同意版・個人文脈の一致をAPIで確認する。詳細は[店舗会員仕様](../membership.md)を参照する。

## 開始案内と発話候補

店舗の`cast.openingInstructions.ja/en`へ開始メッセージ・最初の問いの方針を保存し、下書き・公開・MCPで共有する。省略した旧設定は既定の歓迎案内で動く。開始案内はLiveのdeveloper履歴へ渡し、session.started後にcommentaryを一度だけ送る。同じ来店の履歴があれば短い再開案内とする。客の発話前の委任は参照専用で注文操作を許可しない。

答えやすい提案と1問で導き、登録情報を根拠とする発話候補を最大3件表示する。候補生成は音声を待たせず、選択した文だけを標準Responsesの利用客入力へ送る。候補の表示を承認と扱わず、停止・発話・言語変更で古い候補と遅着を破棄する。同じ字幕は一回、一接続は最大120回とし、予約に会話本文を複製しない。会員の会話本文は候補生成へ再送せず、一般的な候補を使う。

商品・選択肢・カート行のIDは内部の照合とツール引数だけで使う。客には商品名・特徴・表示順で対象を確認し、IDの存在を案内したり、読み上げ・入力・発話・確認を求めない。発話候補と推論要約にも内部IDを含めない。ツールの処理表示は用途と進行状態を示し、内部IDを含み得る生の検索引数は公開しない。旧イベントに検索引数が残っていても描画しない。

数字の表記は数量・価格・時間・容量を含め算用数字とする。例は1,280円・30秒・90mLで、音声は桁読みせず自然に発音する。商品などの固有名詞と保存済み会話の原文は一括変換しない。

## 多言語の商品紹介

接客言語は店舗で有効なBCP 47コードを卓セッションに保持する。最初の商品紹介では意味訳と転写の両方を自然に伝え、その後は`speechName`、未指定なら転写を呼び名に使う。銘柄の固有名を残し、純米吟醸等の種別は相手の言語で説明する。長音記号を含む転写を保持し、fallbackした英語・日本語の商品名があっても会話全体をその言語へ切り替えない。画面の上下表示を読み上げ用の括弧付き文字列へ変換しない。
