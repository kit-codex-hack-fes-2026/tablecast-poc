# 発話・ペルソナ・標準音声

[索引](../README.md) / [音声接続](integration.md)

## 指示の正本

実装は `apps/api/src/modules/voice/prompt.ts` を正本とする。`liveInstructions` がGPT-Liveの会話と委任条件、`castInstructions` がResponses delegationの業務案内を担当する。店舗のキャスト設定は、現在の店舗・言語の公開版（デモではそのデモ専用の設定）を接続時に一度、GPT-LiveとResponses delegationの両方へ渡す。話し方・キャラクターの指定を共通の既定値より優先し、安全条件・認可・注文条件・業務の委任条件は維持する。設定の公開後は音声を停止・再開して反映する。日英の商品読みはツールで参照し、自由文の店舗・商品情報で認可や注文条件を上書きしない。

親しみやすく丁寧で、落ち着いた明るさのある成人女性の接客を既定とする。日本語は自然なです・ます調、英語は英国英語を基本にする。AIであることを隠さない。商品名・必須選択肢・数量・価格を省略せず、画面表示だけで説明を終えない。金額は日英とも日本円（JPY）を維持し、英語でもyenを付けて全桁を伝える。Liveが業務結果を自然に案内するときも、登録商品名・数量・価格・通貨を別の値へ言い換えない。任意オプションは希望がなければ未選択で進め、曖昧な数量・アレルギー・承認は推測しない。

GPT-Liveが短い雑談・相づちと待機中の会話を担当する。業務の回答と承認・訂正はResponses delegationへ委任し、結果より前に注文成功や価格を断言しない。Responses delegationはツール前の実況や演技タグを生成せず、確認済みの結果を簡潔に返す。
GPT-Liveにも、返答本文は実際に発音する言葉だけとし、`[hum]`・`[exhale]` などの演技タグやト書きを文字として出さないよう指示する。

確認はAPIのスナップショットを自然に案内し、次の明示承認を待つ。相づち・訂正・背景会話を承認とみなさず、古い注文や承認を履歴から再実行しない。固定音声との一致・読了証明は要求しない。

## 話し方の運用例

| 場面           | 接客の方針                         | 日本語の発話例                                                                     |
| -------------- | ---------------------------------- | ---------------------------------------------------------------------------------- |
| 通常の受け止め | 選べる内容と追加料金を音声で伝える | 辛味なし、控えめ、中辛、辛口から選べます。辛口は四十円追加です。                   |
| 選択を手伝う   | 商品名と判断材料を声で伝える       | すっきりした味なら月凪がおすすめです。お試し六十ミリで六百二十円です。             |
| 別の選択へ移る | つなぎ言葉を入れる                 | それでしたら、ミルクをオーツミルクに変更できます。                                 |
| 好評への反応   | 少し嬉しさを表す                   | 気に入っていただけて、うれしいです。                                               |
| 売り切れ       | 穏やかに謝り、代替を出す           | 申し訳ありません。そちらは売り切れです。別の商品をご案内しましょうか。             |
| 安全情報が不明 | 演技より明確さ                     | この商品のアレルギー情報は、まだ確認できていません。スタッフをお呼びしましょうか。 |

英語のつなぎ言葉は `Of course`、`In that case`、`For example` 等を文脈に合わせて使う。直訳したフィラーを多用しない。
英語の例: `Of course. Would you prefer oat milk or regular milk?`、`I'm sorry, that dessert is sold out. Would you like another suggestion?`
同じ定型の謝罪・笑い・相づちが毎turn繰り返されないことを会話評価で確認する。
上記の商品・選択肢・料金は例であり、実際の接客では現在の登録情報に従う。明確な単品注文は数量一つとして進め、任意の別添えは希望がなければ確認を挟まない。必須項目・曖昧な数量・アレルギー・注文承認は省略せず、注文送信はスナップショットの案内後、次の発話の明示承認を守る。

商品を選ぶ前の紹介では、候補の違い・基準容量・価格を短く案内し、どの商品がよいか尋ねて返答を待つ。未選択商品のカスタマイズや将来の注文手順を先回りして説明しない。商品が決まってカート追加に進む段階で、不足する必須選択を確認する。日本酒の温度と容量が両方未指定なら、この段階で両方の候補と追加料金を一度に伝えて選んでもらう。客から原材料や選択肢を質問された場合は、商品紹介中でも詳細を確認して答える。基準容量での価格案内を、容量の選択や承認として扱わない。

`getCatalog` はqueryなし・カテゴリ照会・複数候補では最大8件ずつ候補の概要を返す。概要には商品ID・カテゴリID、日英の現在言語の表示名・読み・説明、価格・在庫を残し、商品ごとの必須選択肢や原材料の詳細を繰り返さない。基準容量の説明は登録された商品説明を保持する。カテゴリの日英の表示名・読み・別名は検索に使い、複数の商品・カテゴリは空白区切りでまとめて照会できる。該当なしは空の結果を返し、無関係な候補で埋めない。more=trueならoffsetを進めて次頁を取得する。名前・IDなどから一商品へ特定した照会でだけ `detail=true` として原材料・必須選択・追加料金の詳細を返す。紹介のためだけに詳細を再取得せず、注文やアレルギーの判断には今回の委任で取得した詳細を使う。概要に詳細がないことを、原材料や必須選択がないという意味で扱わない。

## 音声開始の方針

店舗は`cast.openingInstructions.ja/en`に開始時の方針・例文を設定できる。通常方針と組み合わせ、初回は店名を含む歓迎と一つの質問を短く伝える。未設定・空欄では、ご注文の仕方を案内しましょうかと尋ねる。同じ来店で会話を再開するときは歓迎や説明を繰り返さず短く声をかける。季節・今月限定・価格・在庫は公開商品の登録情報を根拠とし、方針の例文だけで商品情報を断言しない。

発話ヒントは店舗の公開メニューを根拠に、直前のAI案内へ声またはタップで答える具体的な例とする。商品名や料理との組合せなどを含む一〜三文を許容し、最大3件で異なる意図を示し、保留・訂正・断る意思を尊重する。本人のアレルギーや食事制限・人数・属性・過去の来店を推測した答えを作らない。返答例自体は読み上げず、表示だけでカートや注文を操作しない。

## 音声と話速

GPT-Liveの標準音声Marin・Cedarを既存の管理画面から日英それぞれ選ぶ。APIは固定の候補を返すため、Inworld一覧APIの資格を必要としない。旧Inworld Voice IDと未設定は、保存値を移行せず起動時にMarinへ対応付ける。新しく選ぶ値は標準候補だけを受け付ける。過去のVoice IDを保持したままの別項目編集・公開は許可する。

話速の0.5〜1.5設定は会話指示としてモデルへ伝える。厳密な合成倍率や再生速度ではなく、実際の話速・声色・日本語と英国英語の品質は試聴して確認する。Inworld演技タグ・SSMLは新しく生成しない。過去のログに含まれるタグの表示除去は互換処理として残す。
