# 音声接客の代表シナリオ

接続後の接客・商品選択・注文確認は音声で完了できることを契約とする。表示は補助であり、必須選択を画面へ押し付けない。価格・販売状態・アレルギー情報・注文の成立は既存のAPIを正本とする。端末の初回マイク・カメラ許可や明示ログインはブラウザーの操作が必要であり、その状態を客に調べさせる代わりにツールの状態と失敗コードで案内する。

| 場面と発話例                                     | エージェントが行うこと                                                                                               | 完了・失敗時の判断                                                                                                                                     |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 初回接続、何を頼めるか分からない                 | 店舗の歓迎案内を1回だけ伝え、おすすめを短く提案して1問で導く                                                         | 自発接客は双方の発話・処理がない30秒後。依頼のない注文操作はしない                                                                                     |
| 読み違いを含む酒と料理を各1つ注文                | getCatalogで候補を特定し、productIdsに解決済みIDをまとめて詳細を取得する                                             | 概要のdetail=falseは詳細が取得不能という意味ではない。requiredSelectionsとカートのmissingを見て詳細照会を続ける                                        |
| 最後のやつとお造り3種を注文                      | getTableStateのdisplayedProductIdsを画面と同じ順で読み、selectedProductIdと直前の会話で対象を絞る                    | 候補の順序を勝手に並べ替えない。対象が曖昧なら商品名で1問だけ確認する                                                                                  |
| 温度・容量などの必須選択                         | APIの選択肢・追加料金・選択数を声で伝え、1問ずつ選んでもらう。商品詳細をsetUiSectionで補助表示する                   | 未指定の項目を推測しない。任意項目は勝手に選ばず、全てを画面で選ぶよう依頼しない                                                                       |
| 選択条件に合わない、売切れ、内容を訂正           | 最新の詳細とmissing・conditionIssuesを使い、条件・利用可能な代替・料金差を声で案内してupdateCartする                 | 過去の版を使い回さず、既存行と指定済みの選択を保つ。失敗を成功と案内しない                                                                             |
| 注文内容を確認して、それで大丈夫です             | prepareConfirmationの品名・数量・選択・合計を読み、次の発話で承認された内容だけsubmitOrderする                       | 同じ発話では承認しない。質問・訂正・曖昧な相づちは承認にしない。GUI変更・言語変更後の古い確認を使わない                                                |
| アレルギーや文化・食習慣を相談                   | 商品IDで現在の登録情報を確認し、不明点は不明と伝える。必要時はcallStaffする                                          | 選択肢を外すことと原材料を抜くことを混同しない。画像・一般知識・本人記憶から安全性を断定しない                                                         |
| カメラで何が見えるか聞く                         | captureCameraで認可後に1枚だけ取得する。getCameraStateで撮影せず状態だけ確認することもできる                         | sessionAuthorizedはAPI認可、camera.statusは端末状態。OFFなら左上のON操作、許可拒否なら許可操作だけ案内する。状態を客へ質問せず、失敗でも音声を維持する |
| 商品を見たい、メニューへ戻る、注文や会計を見たい | 既存setUiSectionでmenu・cart・orders・billを表示する。商品詳細はmenuとproductId、一覧へ戻る場合はproductIdを省略する | 画面遷移だけではカート・注文・会計を確定しない。音声で必要な説明も続ける                                                                               |
| 商品カードとツール結果が追加される               | 商品はコンパクトな横並びにし、最新の発話は追従中だけ下端に固定する。カードと発話候補の追加は共通の短いフェードで示す | 過去の履歴を読んでいる間は追従・固定を解除する。商品名は支援技術へ完全形を渡し、カード選択で詳細を開ける                                               |
| 発話候補を選ぶ、割り込む、言語を変える           | 今の会話に合う最大3件を示し、押した文だけを発言として送る                                                            | 発話・停止・言語変更で古い候補を捨てる。同じセッションの言語切替ではWebRTC接続を作り直さない                                                           |
| もう大丈夫です、今は結構です                     | endConversationで短く挨拶して停止する                                                                                | 注文確認への承認と区別する。送音・再生・生成を止め、カート・注文・履歴を保ち、自動再接続しない                                                         |

商品を特定するIDは内部のツール引数であり、客には認知・発話・入力させない。名前・特徴・表示順から照合し、曖昧なら名前や容量の違いを確認する。発話候補と推論要約もこの契約に従い、ツール表示は生の検索引数を含めない。

## 検証の分担

- APIと実D1はvoice-service-completenessで、日英の複数商品検索、IDによる詳細取得、必須選択、条件の訂正、追加料金、商品詳細とタブの遷移、同じ発話での承認拒否、次の発話での注文成立を確認する。既存の認可・競合・版・言語・停止の試験も維持する。
- Webのvoice-cameraは標準transport境界を固定し、API認可の失敗と端末の撮影許可を区別してモデルへ返すこと、未認可・停止・言語変更後に撮影しないことを確認する。local-camera-readingは実MediaStreamからのJPEG取得・読取・破棄を扱う。
- voice-service-uiとkiosk-layoutはChromium・WebKit・reduced motion、224px・240px・広げた会話欄、ロゴの読込と失敗、カードの収まり、最新発話の固定と履歴スクロール、候補の追加・選択を確認する。ロゴだけはテストケース内のHTTP画像fixtureを使い、終了時に解除する。
- 固定tool呼出しの成功は、実モデルが適切な判断・発話をした証明ではない。上記の発話を実モデル・実音声・実iPadでも確認し、対象SHA、モデル、実際の返答、料金と時間、未実施範囲をPRへ残す。推論要約・字幕・spinnerの到着を返答音声の再生開始とは扱わない。
