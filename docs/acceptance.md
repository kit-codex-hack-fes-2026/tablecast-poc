# 受入条件

[索引](README.md)

これは実装の完了条件であり、本ZIPで達成済みという意味ではない。未測定を合格扱いにしない。

| ID | 合格条件 |
|---|---|
| UI-01 | 客・店側・認証・主要エラーが日英で使え、管理者localeと卓localeが独立する |
| UI-02 | 1024×768の初期画面で会話が主要領域を占め、ログ・言語・停止再開が常設される |
| UI-03 | 客向けに自由文入力欄がなく、全商品・カスタマイズ・注文をタッチだけで操作できる |
| UI-04 | 長い英語、拡大文字、縦画面、reduced motion、キーボードfocusで主要操作が壊れない |
| VOICE-01 | 日本語と英語で検索・説明・カスタマイズ・注文でき、STT/TTSがInworldである |
| VOICE-02 | 演技は状況に合い、好評には嬉しさ、売切には申し訳なさを表し、過度な笑い・フィラーを避ける |
| VOICE-03 | 日本語の外来語と金額を自然に読み、タグ・break・URL・IDを読み上げや字幕へ漏らさない |
| VOICE-04 | 感情は自由文で扱い、Custom Voiceや別モデルfallbackを持ち込まない |
| VOICE-05 | 読上げ途中の訂正で再生が止まり、未再生文を聞いたことにせず、新しい状態へ反映する |
| PAUSE-01 | 明示停止でcapture・送音・認識・生成・再生が終了し、GUI・カート・ログは残る |
| PAUSE-02 | 停止中の言語変更・ネットワーク回復・遅延応答で勝手に再開しない |
| PAUSE-03 | 明示再開で新しいvoice sessionを作り、古い音声を流さず同じ卓の注文を継続する |
| SPEAKER-01 | 実験的な話者ラベル・単語時刻を正しく渡し、欠損や再接続で誤った本人識別をしない |
| ECHO-01 | 無言の客の前でTTSを再生して自己応答ループや無承認送信を起こさない。複数音量で実機検査する |
| ECHO-02 | TTS中の客の訂正は拾える。AECだけで全環境の無誤認識を保証したと記載しない |
| ORDER-01 | 音声とGUIが同じカートを使い、必須選択・数量・売切・価格・プランがAPIで検証される |
| ORDER-02 | 未確認・古いsnapshot・古いturn・二重送信・価格改ざんを拒否し、注文は二重作成されない |
| ORDER-03 | 同時変更、D1 batchの更新0件、途中失敗、成功後の通信断でもカート・注文・金額が整合する |
| ORDER-04 | 音声確認は固定snapshotから読み、訂正で失効する。GUIは停止中でも確認して注文できる |
| DIET-01 | アレルゲン不明・交差接触不明を安全と断言せず、必要に応じてスタッフへ渡す |
| ADMIN-01 | 全卓タイムライン、卓の確定会話・状態・カート・注文・提供・会計を日英で確認できる |
| ADMIN-02 | DO切断・通知失敗後もeventの欠落を回復し、二重表示しない |
| AUTH-01 | 他組織・他店舗・他卓の読書きを拒否し、端末・店員・MCP・Voiceの権限が分離される |
| MCP-01 | メニュー・翻訳・speechName・プラン・キャストを下書き登録、検証、差分確認、承認後公開できる |
| MCP-02 | 権限なしの公開、古い版、LLMが作った承認値だけの要求を拒否する |
| LOCAL-01 | AI API以外はローカルで通常開発でき、実D1/DO/R2とImages対応範囲を使う |
| LOCAL-02 | Web/APIはService Bindingで同一オリジン。別API redirectや広いCORS許可に頼らない |
| WORKTREE-01 | 3つ以上を同時起動してホスト・Cookie・全port・state・LiveKitが混ざらない |

| SEED-01 | demo規模の合成データが決定的に作成され、金額・状態・境界・日英・画像権利を検証できる |

| DEPLOY-01 | Web/APIとPython Agentを公開環境へ配置し、日英実音声・MCP・ダッシュボードが連動する |
| OPS-01 | 生音声を既定保存せず、Secretがログ・ブラウザー・Room名へ漏れず、診断用IDで追跡できる |

## 音声評価の記録

各言語で正しく完了した注文、誤ったカート変更、未承認・誤認識のままの送信、聞き直し回数、遅延を分けて記録する。
危険送信の目標は0件、GUI復旧はすべての試験で成功を目標とする。ただし有限の試験で一般的な無事故を証明したとは記載しない。
TTS自然さは人手試聴、タグ漏れ・数値欠落は機械検査、echoと割り込みはiPad実機で確認する。
録画の動作確認と、騒音条件を変えた評価結果を混同しない。
