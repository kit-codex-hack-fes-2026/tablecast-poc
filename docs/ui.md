# 画面と国際化

[索引](README.md)

## 日英の対象

客向けと店側の全操作UIをja/enにする。ナビゲーション、認証、状態、エラー、空状態、確認、アクセシビリティ名、時刻・金額、プラン残時間を含む。
共通のi18n基盤を `apps/web` に一つ置き、客・店舗・認証・共通のキーを分ける。Paraglide JSを使い、公式TanStack Start構成に合わせる。
英語はイギリス英語を基本とし、通貨はJPYのまま。言語切替で為替換算や店舗タイムゾーンを変えない。

商品表示・読み・aliasはMCPで登録したコンテンツを参照する。固定UI文言を店舗DBへ混ぜない。
保存イベントは言語非依存のコードと構造化値を持ち、各閲覧者の言語で表示する。会話の原文は自動翻訳で置き換えず、発話言語を添える。別翻訳Agentは作らない。

## 客向けの初期配置

基準はiPad横向き1024×768。ヘッダーを除く主領域は会話とメニュー・カートを既定で半分ずつ表示する。境界のつまみをドラッグ、またはフォーカスして矢印キーを押すと、各ペインを30〜70%の範囲で調整できる。狭い画面の縦並びでは高さを調整する。比率はブラウザーに保存し、再読み込みで復元する。調整や並びの変更によって音声接続・会話・表示中の注文タブを作り直さない。
音声を小さい下部バーへ押し込めない。逆に大きな波形だけで面積を消費せず、会話ログを主にする。

```text
┌─────────────────────────────────────────────────────────────┐
│ 店舗・卓番号  [日本語] [English]  [音声を停止] [店員を呼ぶ] │
├─────────────────────────────────┬───────────────────────────┤
│ AI接客・音声受付中               │ カテゴリ                  │
│ 控えめなアバター／状態           │ 商品カード／写真          │
│                                 │                           │
│ お客さま: おすすめは？           │                           │
│ AI: まず、こちらが人気です。     │                           │
│ お客さま: ミルクを変えられる？   │ カスタマイズ              │
│ AI: はい、オーツに変更できます。 │                           │
│                                 │                           │
│ 聞き取り途中の文を一時表示       │ カート・合計              │
│ [最新の会話へ]                   │ [注文内容を確認]          │
└─────────────────────────────────┴───────────────────────────┘
```

日本語・Englishを直接選べる目立つセグメントボタンと、文字付きの大きな音声停止・再開ボタンを常設する。地球儀やマイクのアイコンだけにしない。
主要操作は高さ56px以上を設計値とする。長い英語ラベルでも省略せず折返し・幅調整する。
縦向きでは操作ヘッダー→会話→メニューの順に配置する。任意のメニュー集中表示でも言語と音声停止操作は残す。

## 会話ログ

利用客・AIを視覚的に区別し、確定文、生成・再生中、中断を区別する。話者IDがある場合はSTT stream内で色とIDを揃え、無い場合は未識別と表示する。仮の話者を認識結果として作らない。
初期は現在の卓セッションのみ。古い会話を見ている間は強制スクロールせず、最新へ戻る操作を出す。
SDKの発話字幕を表示し、新しい演技タグは生成しない。過去のInworldタグやSSMLは通常表示から除く。デバッグ切替で、その接続中に受信した原文と店舗の接客プロンプトを確認できる。読み上げ用の語形を会話文に使ってよいが、商品カードは登録表示名のままとする。
聞き取り中・思考中の一時行と履歴は同じ会話部品で表示し、進行中の表示にアニメーションを付ける。入力・出力の実音声から小さな波形を表示する。逐次字幕は確定ログへ二重追加しない。読み上げ前に中断された生成文を発話済みと表示せず、APIの再生済み本文が届いたらそちらへ置き換える。
Agents APIのfunctionイベントからツールの待機中を表示し、APIの実行結果から実行中・完了・エラーへ更新する。実行前にproviderで失敗した呼出しも表示し、停止したturnの未完了処理は中断とする。おしながきの照会では検索語を表示する。通常表示にはそれ以外のツール引数、認証情報、provider例外を出さない。デバッグ表示ではツール名、呼出しID、安全なエラーコードを確認できる。照会単位の失敗では音声回線の接続エラーと表示せず、利用客の次の発話を受け付ける。

字幕を保存済み履歴と同期するときは、表示中の吹き出しの識別子・最初の受信時刻・同時刻の受信順を保つ。保存処理の遅延によって後続の発話やツールを追い越さず、古い保存本文で新しい途中字幕を消さない。
会話のスクロールはAI ElementsのConversation、逐次MarkdownはStreamdownを使う。業務モデルはhosted Agents API、ツール実行は認証済みHonoの共通業務操作を使う。
`aria-live`は新しい確定文の短い通知に限定し、履歴全体や文字ごとの更新を読み直させない。

**客向けのチャット入力欄、送信ボタン、自由文検索欄は作らない。** 商品は音声、カテゴリ、カード、選択肢、数量操作から選ぶ。管理者の設定フォーム・認証入力はこの制限の対象外。

## 停止・再開の意味

| 状態                     | ボタン           | 行動                               |
| ------------------------ | ---------------- | ---------------------------------- |
| 初回・停止中             | 音声を開始／再開 | 利用者操作でマイク許可・接続を開始 |
| 接続中・聞取・思考・発話 | 音声を停止       | 即時に停止処理を開始し連打を防ぐ   |
| 停止処理中               | 停止しています   | 新しい音声操作を受け付けない       |
| 音声障害                 | 音声を再接続     | 利用者が明示的に再試行             |

停止はTTS再生停止、マイクトラックの送信・capture停止、STT stream停止、生成中turnの取消を含む。GPT-Live sessionとAgents APIの生成を明示終了し、業務セッションとHTTP/DO接続は保つ。
単なるマイクmuteをAgent停止と呼ばない。停止中は外部STTへ新規音声を送らず、勝手に再開しない。
停止前に送信済みの音声・DB更新は取り消せない。停止後のカートは最新API状態へ再同期する。
再開後に停止前のTTSの残りを突然再生しない。履歴とカートから必要な確認だけをやり直す。

音声の一時停止で確認読み上げが中断されたら、その音声確認は失効する。現在版を表示したGUI確認は別途作り直せる。

## 入力マイクの選択

速度スライダー右に44×44 CSS pxのマイク設定ボタンを置く。ダイアログで端末の既定マイクとブラウザーが公開する入力を選べる。選択はページ内で保持し、再読み込みをまたいで保存しない。停止中の一覧取得と選択はcapture・送音を開始せず、明示再開で反映する。権限取得前は名前や一覧が制限されるため、音声開始による許可と一覧更新を案内する。

初回と切替時のcaptureはブラウザー標準の`getUserMedia`で取得し、会話中は`RTCRtpSender.replaceTrack`で送信する入力を置き換える。captureの寿命はアプリが管理し、切替完了後は元の入力を止める。切替中も音声停止を優先し、取得済みの新旧入力を止め、遅れて取得した入力も送信せず解放する。古い完了結果を再開や選択変更に使わない。切断・切替失敗時は音声を停止して原因と対処を示し、会話ログ・カートは維持する。既定以外の入力指定が反映されなければ成功表示しない。

[標準WebRTCの入力切替](https://developer.mozilla.org/en-US/docs/Web/API/RTCRtpSender/replaceTrack)と[ブラウザーのデバイス一覧](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/enumerateDevices)を使う。iPad Safariを含め、OS・ブラウザーが公開する入力だけが候補になる。候補が少ない場合は端末側の入力設定を案内し、UA名だけで対応可否を断定しない。複数の実マイクでの切替・切断、実iPad Safariの入力選択は実機検証が必要であり、Storybookや合成音声の成功では代替しない。

## 言語変更

客が選んだ言語はGUI、AI応答、TTSへ反映し、カート・注文を保持する。一文のSTT言語推定で勝手に切り替えない。
変更時に発話中なら中断し、STT/TTS設定を切り替える。停止中なら停止状態を維持し、言語変更だけでマイクを開かない。
過去の原文ログはそのまま。AIの新しい発話から選択言語を適用する。技術タグの英語は利用客へ表示しない。

## メニューと注文

商品カード、商品詳細、必須・任意カスタマイズ、カート、確認画面を用意する。不足項目はカートに表示し、編集操作またはAgentの個別商品遷移で対応する選択UIを開く。
選択肢にも商品と同じメディア参照を設定でき、単一選択・複数選択・数量指定の行で写真と日英の名称・説明・差額を一緒に表示する。商品と選択肢の写真は正方形の枠へ全体を収め、選ぶ対象を切り抜かない。イメージ・売切の表示は画像の外に置き、写真を覆わない。写真は比較の補助とし、選択状態・売切・数量操作は文字とコントロールで伝える。画像なしは文章だけの行、読込失敗は画像枠内の代替アイコンにし、選択や保存を妨げない。選択肢の説明は読み上げ支援へも関連付ける。
会話にも同じ商品カードを最大4件表示し、選択すると右ペインの商品詳細ページを開く。商品詳細・オプション・注文確認はモーダルにせず、同じペイン内に表示する。Agentは公開カタログにある商品IDだけを指定し、価格・売切・選択肢はAPIのカタログから表示する。
おしながき・注文かご・注文済み・お会計の選択タブは卓状態の `uiSection` として保存する。商品詳細は `selectedProductId` を共有し、`PATCH /api/table/ui` と `setUiSection` の `productId` で開閉する。別タブへの移動では詳細選択を解除する。GUIの `PATCH /api/table/ui` とAgentの `setUiSection` は同じ認可済み操作を使う。Agentは `getTableState` で現在のタブを読み、利用客の依頼に沿って切り替える。
確認画面は商品・変更・数量・金額を省略しない。同じスナップショットを音声で読み、訂正とGUI確定の両方を提供する。
会話内の確認カードからも現行スナップショットのGUI確認を開ける。カード表示やタブ切替だけでは注文を確定しない。
音声が壊れても全画面エラーへせず、会話側に状態を出してGUI注文を継続する。

## 店舗画面

`/admin/stores/:storeId/floor` に全卓のTanStack Tableを置く。旧 `/admin/live` は対象店舗のページへ転送する。上部に稼働卓、要対応、会計待ち、音声異常の集計を表示する。
列は卓・人数、経過、卓状態、音声状態、客の使用言語、時間軸、未確定カート、注文済、未会計、要対応、最終更新。
優先順は要対応→会計待ち→音声異常→利用中→空席。並び順の頻繁な自動変更で操作中の行を飛ばさない。

卓の詳細は `/admin/stores/:storeId/visits/:sessionId` に表示する。概要・ログ・注文・会計・診断は `view` 検索値で再現する。詳細表示にDialogやSheetを使わない。
提供・支払登録は権限を検証し、失敗を成功表示しない。診断IDやraw provider errorは通常の業務欄に出さない。
スタッフがEnglishにしても客の日本語セッションは変更しない。英語の業務イベント表示と、日本語原文の会話ログが共存できる。

過去の来店は履歴から参照する。店舗ごとに閉卓日時の新しい順で卓・人数・日時・会計総額を表示し、続きを読み込めるようにする。同時刻の来店も区別し、店舗変更後に前の店舗の履歴を残さない。
履歴から開く詳細では、保存済みの注文と会計、原文の会話・操作ログを表示する。古いログも遡れるようにし、提供・支払・呼出解除・閉卓の変更操作は表示しない。

## 部品とStorybook

Base UIのDialog、Drawer、Radio Group、Checkbox、Number Field、Tabs、Alert Dialog等を必要な範囲で使う。見た目を揃える部品だけを `apps/web/src/components` に置き、全APIを包む独自UIライブラリは作らない。
Storybookは `apps/web/.storybook` と部品に隣接するStoryで十分。独立配布するUI製品でも複数Webアプリでもないため、`apps/storybook` を増やす理由はない。[S14](sources.md#s14)

日英、長い商品名、停止・再開、許可拒否、接続中、割込、エラー、確認失効、画像なし、売切、要対応卓をStoryで再現する。
Storyには実OpenAIを接続せず、同じ表示部品へ固定状態・操作を渡す。実際のマイク停止・再接続は統合試験で確認する。

## 会話と音声操作の配置

タブレットでは会話・メニューを並べ、両ペインを独立スクロールにする。波形・停止／再開・話速は会話の下にまとめる。話速は `speechSpeed`、既定1倍、範囲0.5〜1.5倍・0.1刻みで卓に保存し、音声Agentが2秒周期で同期して次のTTS contextに適用する。
会話は初期表示と逐次更新を自動追従し、履歴を上へスクロールしたら解除する。最新へ戻るボタンから再開できる。空の確定・中断吹き出しを表示せず、ツール結果は対象発話の近くに置く。話者情報のない発話はお客さまと表示し、debugで欠損を明示する。
カートは商品画像・数量増減・オプション編集を備え、数量変更もAPIの版検査と価格計算を通す。

AgentのsetLanguageはGUIと同じ言語変更処理を使い、音声と古い確認を停止・失効させる。新言語の音声は画面から明示再開する。setSpeechSpeedはGUIと同じ範囲・刻みを検証し、次の発話へ適用する。
発話の話者は識別済み単語の多数決で決める。同数・全語未識別では話者を未設定とし、エラーにせず会話を続ける。

基本色は白・黒・無彩色とし、文字は高コントラストを保つ。ボタンは半透明の白と内外の控えめな影で立体感を付け、音声操作は黒地・白文字・虹色リングで区別する。

音声orbはPaper ShadersのSmokeRingを使用し、状態間の形と流速をMotionで補間する。聞き取りは緩やかな波とマイク、思考は密な揺れと星、ツール実行は細い輪・破線と工具、発話は波の変形と音声記号で区別する。実音声の音量で半径、周波数の分布で波の細かさを変える。横の波形は実音声を示し、無音の思考や処理中は架空の音声波形を作らない。声かけ中にツールが動いていれば発話状態とツール実行表示を併記し、停止後の古いツールイベントを処理中と表示しない。

停止・エラー時は静止し、動きを減らす設定ではshaderと装飾アニメーションを停止する。画面が非表示の間はshaderと音声解析の描画更新も止める。状態は色や動きだけに依存せず、文字と記号でも伝える。カード・商品ページは補助であり、必要な選択肢や判断材料は音声でも伝える。

## 管理コンソールの表示基準

`enterprise-agentic-saas-starter`のConsoleShell/ConsoleFrameに合わせ、店舗切替・ナビゲーション・ユーザーメニューを左側、固定ヘッダーと角丸の主領域を右側へ配置する。狭い画面ではサイドバーを開閉する。店舗作成・招待・端末登録は個別ページへ移動する。

管理サイドバーは境界のつまみで幅を調整する。既定16rem、通常14〜24rem、折りたたみ時4.5remとし、ブラウザーに幅を保存する。矢印キーでも操作できる。主領域とサイドバーの一覧は画面内で独立してスクロールし、狭い画面では幅調整を外して従来の開閉ナビゲーションにする。共通の仕切りはshadcnと同じ`react-resizable-panels`を使い、寸法の制約・保存・キーボード操作を独自実装しない。

本文・入力・主操作は16px、補助情報は14px以上を基本とし、既定の文字色は`#18181b`、補助色は`#3f3f46`とする。操作領域は44px以上を基本とする。白背景を基準にし、OSのダークモードで一部の入力だけが暗くならないようにする。選択状態は背景と太さで示し、キーボードフォーカスを明示する。音声の虹色は維持する。

初期読込でもコンソール枠を維持し、スクロールバー領域を予約する。ユーザーは画像または頭文字、名前、メールを一緒に表示する。Googleはロゴ、破壊的な操作は赤とアイコン、現在の端末はテキスト付きの印で識別する。

## 管理画面のページ構成

店舗=組織であり、店舗配下にメンバーと端末を置く。操作を持つ一覧は共通DataTableとTanStack Tableを使う。選択前から現在の項目、日時、状態、操作を表示する。役割はアイコンと色のBadge、削除・取消はdestructiveの操作として区別する。

メニューは `/admin/stores/:storeId/menu/:section` の商品・カテゴリ・プラン・接客設定に分け、項目詳細は `/:itemId` に置く。現在の設定は閲覧用の表示と一覧で見せる。変更作成後は `/menu/changes/:draftId/:section/:itemId` で編集し、`/menu/changes/:draftId` で差分の検証と店舗への反映を行う。未保存の変更を残した移動は確認する。サイドバーのメニュー・接客をBase UI Collapsibleで展開し、各子ページと変更一覧を表示する。ページ内の重複タブは置かず、直接URLを開いた際も子ページを展開して現在地を示す。下書き編集時の子ページは同じ下書き内を移動する。

商品一覧は画像・名前・カテゴリ・価格・販売状態を表示し、日英の名前・別名・カテゴリ名を検索できる。カテゴリと販売状態の絞り込み、検索語、ページ位置はURLの`q`・`category`・`availability`・`page`に保持し、詳細・下書き編集・公開確認・公開後の一覧へ引き継ぐ。店舗切替では別店舗の条件や入力を引き継がない。カテゴリには所属商品数と商品名、プランには価格・利用時間・ラストオーダー・指定対象の概要を表示する。初回読込、通信失敗、未登録、条件に一致しない0件を区別し、再取得に失敗しても取得済みの一覧を残す。

設定の編集開始では再開する下書きと新規作成をダイアログで選ぶ。再開候補は編集中・検証済みの下書きだけを更新時刻順に30件ずつ取得し、作成元公開版、下書き更新番号、変更対象と現在公開版からの差分件数を表示する。続きはカーソルで読み込み、候補一覧へ全設定・差分本文を返さない。MCPと既存履歴一覧のAPIは維持する。

店舗名・現在公開版・下書き識別子・作成元公開版・下書き更新番号をヘッダーと展開中のナビゲーションに表示する。編集フォームでは未保存、保存中、失敗、競合を重ねて示す。下書きIDがURLに残る場合もAPIのstatusから操作可否を決め、公開済み・破棄済みは閲覧専用とする。店舗を切り替えたときは以前のフォーム状態を引き継がない。

保存後は変更確認・検証へ進み、検証エラーのある設定へ戻れる。公開は変更内容・反映対象・タイミングを確認するダイアログの明示操作で行う。公開時は利用中の卓を含むメニューが更新され、未確定の注文確認は失効する。確定済み注文金額と適用中のプラン条件は維持する。公開後は公開中の各設定へ戻れる。作成元より公開版が進んでいる場合は公開不可と入力保持を示し、別の下書きを作成できる公開画面へ案内する。

未保存入力を戻す操作は最後に保存した値へ戻し、下書き全体の破棄とは別に確認する。保存失敗・競合では入力を保持し、同じ保存操作を再試行できる。下書き更新番号の競合では、未保存入力を破棄することを確認した後だけ最新の保存済み下書きを読み込む。ページ離脱と再読み込みの未保存保護を維持する。

管理者の商品編集では、選択肢ごとに画像参照と写真・イメージの種別を設定し、プレビューと既存の日英説明欄で確認する。商品詳細の選択肢一覧にも同じ画像と説明を表示する。変更は既存の下書き保存・検証・人間の公開承認を経て客向けに反映する。

商品と選択肢の画像入力は共通部品を使い、ファイル選択と既存画像指定を分ける。通常はPNG・JPEG・WebPの5 MB以内・1,600万画素以内を取り込み、現在の編集画像と選択候補を別々に確認する。既存参照の直接指定は上級設定に置き、`tablecast/menu/photo.webp`のような保存済み参照であり端末のファイルパスではないことを説明する。取込には出所と生成画像の申告を必要とし、生成画像の種別はイメージにする。店舗所有・存在・種別・出所は既存APIが検証する。

画像の取込成功時だけ編集参照を置き換える。取込中・再試行・形式や容量のエラーを日英で案内し、失敗しても元の画像参照・選択ファイル・他の入力を保持する。画像なしと読込失敗を区別し、置換と解除をキーボードでも操作できる。取込・置換・解除と下書き保存・明示公開は別操作として説明し、画像部品から保存や公開を実行しない。

商品・選択肢の取込中は、同じ店舗の全画像取込が完了するまで親フォームの保存・削除・画面移動を止める。ブラウザー終了時には未保存内容と同様に確認し、PWA更新も待機する。React Queryの店舗別mutation keyで複数画像の進行を集計し、操作時点のpendingを確認する。取込後は画像を含む最新の入力を下書き保存する。

取込前の選択候補や未適用の画像入力も未保存として扱い、取込失敗後も離脱確認とPWA更新の待機を維持する。画像の入力を戻す操作で候補と未適用入力だけを破棄できる。画像解除と別ファイルの選択では、元画像の種別・生成申告・出所を引き継がず再入力を求める。同じファイルの再試行では入力を保持する。

店舗アイコンは `/admin/stores/:storeId/profile` で管理者が設定する。組織の`logo`を正本とし、店舗一覧・切替・設定ページでは角丸の正方形、ユーザー画像は丸形にする。PNG・JPEG・WebPの1MB以内を受け付け、ユーザー画像と同じ検証・R2保存経路を使う。

MCP・Skillsの管理はプラグイン導入、手動導入、OAuth接続に分け、各ページをURLで再現する。店舗の利用者へ公開HTTPS MCPとOAuthの接続を案内し、cloneやローカル開発環境を要求しない。公式ガイド、公開pluginと同じ本番接続URL、CLI設定のコピー、同梱SKILL.mdの任意ダウンロードを用意する。接続URLは`plugins/tablecast/.mcp.json`を参照し、表示用に複製しない。OAuth接続一覧はアプリ・店舗・scope・状態・承認日時・更新日時・アクセストークン期限・更新トークン期限・解除操作をTanStack Tableで表示する。

## 初期表示と非同期状態

初期データはroute loaderで取得し、SSRとブラウザーで同じqueryOptionsを使う。遷移待ちは寸法を予約したSkeleton、失敗は再試行可能なerror boundary、取得成功時の空配列は0件として表示する。更新に失敗しても取得済みデータを残し、失敗を空の結果へ変換しない。短いopacityの出現アニメーションとSkeletonのpulseは`prefers-reduced-motion`に従う。

JSが必要なボタンと入力はTanStackの`useHydrated`で操作可能になる時点を揃える。SSRの見た目だけが先に届いた状態で、入力や注文操作を取りこぼさない。金額の円記号はICUによる全角・半角の差を正規化する。フロアの経過時間の初期値にはSSR queryの取得時刻を使う。

ペイン幅は`tablecast-layout-`から始まるCookieへ保存し、SSRでも同じ幅を描く。Cookieから画面へ渡すのはこの表示設定だけで、認証Cookieは含めない。以前のlocalStorageだけに保存された幅は初回に既定幅となる。表示設定の破損は既定幅へ戻し、画面を停止させない。

商品と選択肢の画像はUnpicの`srcset`・`sizes`と幅・高さを持ち、R2/Imagesから必要な大きさのWebPを取得する。配信幅は1〜1600px、未指定時は640px。幅ごとのETagが一致するときは画像を再変換しない。音声停止中は同じ高さの静的表示を使い、波形・WebRTC接続のコードは音声の開始時に読み込む。

### 設定フォームの配置

商品・カテゴリ・プラン・接客設定・店舗プロフィールは、ページ見出し、セクション、反復行、項目の順に階層を揃える。基本情報、価格・販売状態、名称・翻訳、画像、安全情報、カスタマイズ、プランの制限・対象を意味ごとに分ける。セクションは上罫線と24px以上の間隔、内部は16〜20pxの間隔を基本とし、枠の入れ子を増やさない。ページはh1、セクションはh2、グループはh3、選択肢はh4とする。

フォームの列数は画面幅ではなくコンテンツ領域のcontainer queryで切り替える。sidebarの幅変更・iPad縦横・文字拡大で入力領域が狭くなった場合は一列に戻し、ラベルを折り返す。チェックボックスの文言はチェックと横に並べ、祖先要素から全ラベルの配置を上書きしない。

反復行は通し番号と名称を常に表示し、選択方式・選択数・追加料金・最大数量・販売状態を同じ順序で比較できるようにする。長文の翻訳、画像、組合せ条件は標準detailsで展開する。入力は折畳み中も保持し、保存時に必須項目が不正なら該当する詳細を開いてフォーカスする。行と入力のDOMは安定したIDをkeyにし、追加後は新しい行見出し、削除後は隣の行見出しへフォーカスを移す。同名行でも対象グループ・選択肢・言語・項目をaria-labelledbyで区別する。

Lucideは追加にPlus、削除・破棄にTrash2、保存にSave、公開にUpload、履歴にHistory、画像にImageまたはImagePlus、戻る操作にArrowLeftを使う。主要操作はアイコンと文言を併記し、装飾アイコンはaria-hiddenにする。アイコンのみの操作には既存Tooltipとaccessible nameを用い、タッチでも操作の意味を確認できる説明を残す。展開操作は44px以上のタップ領域とフォーカス表示を持つ。公開・破棄・履歴の動作と位置は共通の変更管理を使い、各フォームへ複製しない。

現在の画像入力は商品では画像セクション、選択肢ではその行の詳細内、店舗ではプロフィールの画像セクションへ置く。画像選択・置換・解除の内部操作を変更しても、この対象とラベルの対応を維持する。

### フォームと操作結果

ログイン、登録・パスワード再設定、店舗作成、招待、プロフィール・パスキー名、端末登録、開卓、会計入力はTanStack Formで入力・validation・送信状態を管理する。項目エラーはBase UI Fieldによりラベルと説明へ関連付け、`aria-invalid`・`aria-describedby`で取得できる。日英の修正案を表示し、失敗しても入力を保持する。送信中は主ボタンを無効化し、支援技術にも送信中を伝える。

保存・送信結果は寸法を確保した共通表示で切り替える。Motionの入場は160ms、退場は100msでopacity・transformを使い、reduced motionでは移動を止める。フォームの入力・フォーカスは切替中も維持する。

## iPadのホーム画面アプリ

客向け `/` と店側 `/admin/live` は別のmanifest ID・起動先を持つ。Safariの共有からホーム画面に追加し、追加したアプリ内で端末登録またはログインする。双方を別アイコンとして追加でき、縦横の向きを固定しない。追加方法は画面末尾で日英表示し、standaloneでは隠す。

Web更新は起動・前景復帰・通信復帰と前景中60秒ごとに確認する。接客中の卓、端末登録の承認待ち、未保存フォーム、mutation・画面遷移中は適用しない。同じService Worker配下の全画面が応答して安全な場合のみ、短時間操作を止めて有効化・再読み込みする。応答なし・休止中の画面があれば待機し、次回復帰・起動時に再確認する。

オフラインでは取得済みの画像を再利用する。新規起動・ページ移動に失敗した場合は日英の復帰案内を表示する。注文・音声・認証はオンラインを必須とし、送信予約やAPI応答の永続キャッシュは持たない。
