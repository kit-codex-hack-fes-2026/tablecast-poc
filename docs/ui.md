# 画面と国際化

[索引](README.md)

## 日英の対象

客向けと店側の全操作UIをja/enにする。ナビゲーション、認証、状態、エラー、空状態、確認、アクセシビリティ名、時刻・金額、プラン残時間を含む。
共通のi18n基盤を `apps/web` に一つ置き、客・店舗・認証・共通のキーを分ける。Paraglide JSを使い、公式TanStack Start構成に合わせる。
英語はイギリス英語を基本とし、正式な価格・注文・会計はJPYを維持する。店舗タイムゾーンは言語で変えない。客向けと注文デモだけに外貨の参考額を補助表示できる。

商品表示・読み・aliasはMCPで登録したコンテンツを参照する。固定UI文言を店舗DBへ混ぜない。
保存イベントは言語非依存のコードと構造化値を持ち、各閲覧者の言語で表示する。会話の原文は自動翻訳で置き換えず、発話言語を添える。別翻訳Agentは作らない。

### ブラウザーのタイトルと概要

全Web routeは、画面名と概要の日英キーを`staticData.document`に持つ。店舗・商品・卓などの対象名は取得済みloaderから`document`へ渡し、表示名・画面名・店舗名・TableCastの順でタイトルを作る。内部ID・ハッシュ・メール・注文や記憶の内容はheadへ出さない。未解決時はTableCast、404・取得失敗時は対象名を残さない日英の状態名を表示する。

`DocumentHead`をLocaleProvider内の唯一のtitle・description所有者とし、Reactの標準head配置を使う。言語変更はデモの一時変更も含めて即時に追従し、言語変更のための追加取得やRouter再検証をしない。商品名の保存・再取得後は、対象ルートのページ情報を更新済みQueryから再評価する。TanStackのheadはloader処理で評価されるため、言語だけの変更に再取得を伴わせないこの配置とする。`HeadContent`はcharset・viewport・アイコン・manifest・配信アセットを引き続き所有し、title・descriptionを重複させない。SSR HTMLと画面遷移の両方で各1件を確認する。

### 外貨の参考表示

円を先に置き、`¥1,000 ≈ A$9.67` の1行で表示する。円・外貨とも既存の文字サイズ・太さを引き継ぎ、外貨は補助色だけで区別する。商品・選択肢の追加料金・プラン・カート・確認・注文履歴・会計に同じ設定を適用し、管理・会員画面や請求通貨は変更しない。言語の右の通貨セレクタはCoinsアイコン、国旗、記号・ISOコード（`£ GBP`、`A$ AUD`）を示し、円のみの状態はJPYとする。メニューに正式名称、`1 AUD ≈ ¥…`、基準日、外貨は目安で支払いは円である旨を日英で示す。

東アジアのCNY/HKD/TWD/KRW/MOP/MNT/KPW、東南アジアのSGD/THB/VND/MYR/IDR/PHP/BND/KHR/LAK/MMK、USD/GBP/EUR/AUD/NZDを初期対応とする。日本語の初期値は外貨なし、英語はUSD。未操作なら言語と連動し、手動または接客エージェントによる明示選択後は言語を変えても維持する。端末・来店ID単位で保存し、別端末へ共有しない。同じ来店の再読込は復元し、次の来店へ前の選択を引き継がない。

画面初期化時にだけ認証済みAPIからレートを一括取得し、通貨変更・タブ復帰・通常操作で再取得しない。円からの換算結果を通貨標準の桁へ丸め、合計は円の合計から換算する。取得中・取得不能なら円だけを表示し、セレクタ内で取得状態を示す。通貨変更だけで音声・カート・確認snapshotを作り直さない。

## 客向けの初期配置

基準はiPad横向き1024×768。会話欄は約240pxから始め、写真と注文内容に主領域を使う。境界はドラッグ・キーボードで調整でき、横向きと縦向きの調整値を別々に保持する。回転、設定ダイアログの開閉、メニュータブ切替で音声接続・会話・カートを作り直さない。

会話欄には映像のソース比率を保つカメラ枠、音声状態、カメラON/OFF、音声停止・再開を近接配置する。OFF・許可待ち・失敗でも同じ枠を保つ。カメラは明示ONで有効にし、認可済みのcaptureCameraが必要時に1枚だけ画像をAIへ送信する。連続映像の送信・録画・画像保存は行わない。非表示・離脱でtrackを解放し、自動再開しない。許可待ち中のOFF後に遅れて取得したstreamも解放する。

カメラは会話欄の左上に初期幅128px・未取得時4:3で表示する。metadataからソース比率へ追従し、映像を切り抜かない。右下の44pxリサイズ入口をドラッグ・タッチ・方向キーで操作でき、Home/Endで最小/最大へ変更できる。映像枠は幅320px・高さ240pxと会話欄の利用可能領域を上限にし、OFF・許可待ち・失敗でも直前の比率と調整幅を保つ。
ON/OFF・機器選択・内側／外側切替は映像枠の外、下側の左寄せの操作列へ置き、44pxの操作領域を保って必要時に折り返す。ON/OFFを左端へ固定し、他の操作の出現で横へ移動させない。機器選択は複数機器がある場合に表示し、旧trackと遅着streamを解放する。操作ボタンは半透明にする。OFF・取得待ち・失敗・画像読取りはアイコン・色・spinnerで示し、状態文や送信・録画の注意書きは常設しない。操作名・状態・エラーは支援技術へ伝える。
カメラ枠と操作列の実際の高さに合わせ、スクロールする履歴の先頭へ余白を設ける。先頭の発話をカメラの背後へ隠さず、後続の履歴は全高でスクロールできる。

初期の空の会話履歴には、声でおすすめや料理を相談し注文できることを伝える会話UI型のイラスト・説明と、白色の会話を始めるボタンを中央寄せで表示する。イラストは会話の吹き出し、音声波形、料理とおすすめ、注文、日英の切替を示す。下部の既存再開ボタンの色・文言は変えない。短い会話欄では装飾と補足説明を省いて開始操作を表示内に収める。開始ボタンの外枠だけを2秒周期で3回脈打たせ、接続開始・非表示では停止し、reduced motionでは動かさない。会話のある停止状態へ初期案内や暗幕を重ねない。
会話の商品カードは幅176px以下、画像高96pxの横スクロール行へまとめ、ツールが指定した商品IDの順序を保つ。最新の発話だけを追従中に下端へ固定し、手動で過去履歴へ移動すると固定を解除する。商品カードと発話候補の追加には既存の状態表示フェードを使い、reduced motionで省く。ヘッダーは横長バナーを優先し、未設定なら店舗ロゴを表示する。画像の読込失敗でも店舗名と高さを維持する。
履歴とツールの待機・実行・結果は常時表示し、音声orb・実波形・状態・停止とマイク設定は下端に固定する。下端の既存の開始・再開ボタンの文言・マイク・虹色リングを保ち、マイク設定への入口を初期・停止中も表示する。会話ペインはゴシック体で統一し、セリフ体を使わない。注文確認・失効・エラーも履歴へ表示し、音声状態を読み上げる処理を追加しない。

```text
┌──────────────────────────────────────────────────────────┐
│ 店舗・卓番号  [卓上ゲーム] [QR参加] [言語] [店員を呼ぶ]   │
├──────────────┬───────────────────────────────────────────┤
│ カメラ・操作 │ おしながき／注文かご／注文履歴／お会計    │
│ 会話履歴 ↕  │ カテゴリ                                  │
│ ツール結果   │ 商品写真・名称・価格・カスタマイズ          │
│ orb・波形    │                                           │

│ 音声設定     │ 注文かご・合計・注文内容を確認              │
```

店員呼出は画面右上に置き、言語と通貨のセレクタは右寄せで国旗を添える。言語セレクタは共通の国旗付き日英切替を使い、通貨はCoinsアイコンも表示する。店員呼出は文言を表示し、ゲーム・QR参加は名前付きのghostアイコンにする。言語・通貨・補助操作は54px高へ揃える。言語名付きの切替と音声停止・再開を常設する。国旗は18×14pxの補助表現で、言語名を置き換えない。来店参加・ゲームはヘッダー内の補助操作へまとめ、独立した帯で注文領域を削らない。ゲーム開始時は既存の音声停止を維持する。客向け主操作は56px以上。長い英語の語中や数量の数字を不自然に分割せず、行・幅を調整する。

## 会話ログ

利用客・AIを視覚的に区別し、確定文、生成・再生中、中断を区別する。話者IDがある場合はSTT stream内で色とIDを揃え、無い場合は未識別と表示する。仮の話者を認識結果として作らない。
初期は現在の卓セッションのみ。古い会話を見ている間は強制スクロールせず、最新へ戻る操作を出す。
SDKの発話字幕を表示し、新しい演技タグは生成しない。過去のInworldタグやSSMLは通常表示から除く。客向け画面にはデバッグ操作、生成原文、店舗の接客プロンプトを表示しない。読み上げ用の語形を会話文に使ってよいが、商品カードは登録表示名のままとする。
聞き取り中・思考中の一時行と履歴は同じ会話部品で表示し、進行中の表示にアニメーションを付ける。入力・出力の実音声から小さな波形を表示する。逐次字幕は確定ログへ二重追加しない。読み上げ前に中断された生成文を発話済みと表示せず、APIの再生済み本文が届いたらそちらへ置き換える。
Agents APIのfunctionイベントからツールの待機中を表示し、APIの実行結果から実行中・完了・エラーへ更新する。実行前にproviderで失敗した呼出しも表示し、停止したturnの未完了処理は中断とする。おしながきの照会では検索語を表示する。通常表示にはそれ以外のツール引数、認証情報、provider例外を出さない。内部ツール名・呼出しID・エラーコードは表示しない。照会単位の失敗では音声回線の接続エラーと表示せず、利用客の次の発話を受け付ける。

字幕を保存済み履歴と同期するときは、表示中の吹き出しの識別子・最初の受信時刻・同時刻の受信順を保つ。保存処理の遅延によって後続の発話やツールを追い越さず、古い保存本文で新しい途中字幕を消さない。
会話のスクロールはAI ElementsのConversation、逐次MarkdownはStreamdownを使う。業務モデルはhosted Agents API、ツール実行は認証済みHonoの共通業務操作を使う。
`aria-live`は新しい確定文の短い通知に限定し、履歴全体や文字ごとの更新を読み直させない。

**客向けのチャット入力欄、送信ボタン、自由文検索欄は作らない。** 商品は音声、カテゴリ、カード、選択肢、数量操作から選ぶ。管理者の設定フォーム・認証入力はこの制限の対象外。

## 停止・再開の意味

| 状態                     | ボタン           | 行動                               |
| ------------------------ | ---------------- | ---------------------------------- |
| 初回・停止中             | 音声を開始／再開 | 利用者操作でマイク許可・接続を開始 |
| 接続中・聞取・思考・発話 | 音声を停止       | 即時に停止処理を開始し連打を防ぐ   |
| 停止処理中               | 停止しています   | 新しい音声操作を受け付けない       |
| 音声障害                 | 音声を再接続     | 利用者が明示的に再試行             |

停止はTTS再生停止、マイクトラックの送信・capture停止、STT stream停止、生成中turnの取消を含む。GPT-Live sessionとAgents APIの生成を明示終了し、業務セッションとHTTP/DO接続は保つ。
単なるマイクmuteをAgent停止と呼ばない。停止中は外部STTへ新規音声を送らず、勝手に再開しない。
停止前に送信済みの音声・DB更新は取り消せない。停止後のカートは最新API状態へ再同期する。
再開後に停止前のTTSの残りを突然再生しない。履歴とカートから必要な確認だけをやり直す。

音声の一時停止で確認読み上げが中断されたら、その音声確認は失効する。現在版を表示したGUI確認は別途作り直せる。

## 入力マイクの選択

会話欄下端に44×44 CSS pxの設定ボタンを置き、Slidersアイコンで示す。設定ダイアログへ話す速さ、入力マイクをまとめる。話速の確定後もSliderを作り直さず、キーボードの連続操作とフォーカスを保つ。カメラ映像は会話欄へ残す。端末の既定マイクとブラウザーが公開する入力を選べる。選択はページ内で保持し、再読み込みをまたいで保存しない。停止中の一覧取得と選択はcapture・送音を開始せず、明示再開で反映する。権限取得前は名前や一覧が制限されるため、音声開始による許可と一覧更新を案内する。

初回と切替時のcaptureはブラウザー標準の`getUserMedia`で取得し、会話中は`RTCRtpSender.replaceTrack`で送信する入力を置き換える。captureの寿命はアプリが管理し、切替完了後は元の入力を止める。切替中も音声停止を優先し、取得済みの新旧入力を止め、遅れて取得した入力も送信せず解放する。古い完了結果を再開や選択変更に使わない。切断・切替失敗時は音声を停止して原因と対処を示し、会話ログ・カートは維持する。既定以外の入力指定が反映されなければ成功表示しない。

[標準WebRTCの入力切替](https://developer.mozilla.org/en-US/docs/Web/API/RTCRtpSender/replaceTrack)と[ブラウザーのデバイス一覧](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/enumerateDevices)を使う。iPad Safariを含め、OS・ブラウザーが公開する入力だけが候補になる。候補が少ない場合は端末側の入力設定を案内し、UA名だけで対応可否を断定しない。複数の実マイクでの切替・切断、実iPad Safariの入力選択は実機検証が必要であり、Storybookや合成音声の成功では代替しない。

## 言語変更

客が選んだ言語はGUI、AI応答、TTSへ反映し、カート・注文を保持する。一文のSTT言語推定で勝手に切り替えない。
変更時に発話中なら中断し、STT/TTS設定を切り替える。停止中なら停止状態を維持し、言語変更だけでマイクを開かない。
過去の原文ログはそのまま。AIの新しい発話から選択言語を適用する。技術タグの英語は利用客へ表示しない。

## メニューと注文

商品カード、商品詳細、必須・任意カスタマイズ、カート、確認画面を用意する。写真が未登録の商品は小さな画像なし表示と名前・価格を中心にし、大きな仮画像枠でメニュー面積を消費しない。登録画像の読込中・失敗は画像の寸法を維持する。画面外の商品写真は、正方形の寸法を保った画像枠に`content-visibility: auto`とnative lazy loadingを併用する。商品名・価格・操作は省略せず、スクロール先の写真も表示する。実幅に合う画像候補を取得し、24/120商品の転送量とCLSは既存予算を維持する。不足項目はカートに表示し、編集操作またはAgentの個別商品遷移で対応する選択UIを開く。
選択肢にも商品と同じメディア参照を設定でき、単一選択・複数選択・数量指定の行で写真と日英の名称・説明・差額を一緒に表示する。メニューとカスタマイズ選択欄の写真は正方形の枠へ全体を収め、選ぶ対象を切り抜かない。カゴと履歴のカード写真も余白の内側へ角丸付きで左上に揃え、元の縦横比を保つcontain表示とし、切り抜き・引き伸ばしをしない。イメージイラストの注記は10pxの控えめな文字と小さい内側余白で画像上の下端へ重ね、売切は画像の外に表示する。写真は比較の補助とし、選択状態・売切・数量操作は文字とコントロールで伝える。画像なしは文章だけの行、読込失敗は画像枠内の代替アイコンにし、選択や保存を妨げない。選択肢の説明は読み上げ支援へも関連付ける。
会話にも同じ商品カードを最大4件表示し、選択すると右ペインの商品詳細ページを開く。商品詳細・オプションは注文ペイン内の非モーダルDialogへ表示する。商品写真は左上へ128〜160pxで比率を保って表示し、閉じるボタンは右上に置く。注文pane内の背景だけに薄いoverlayを置く。Dialog外側の余白は狭幅16px・通常24pxとする。外側24px・ヘッダー内側余白16px・画像と閉じる操作の角丸8pxで中心を揃える。内容だけをスクロールさせ、閉じる・数量・追加操作は固定する。選択項目の必須・任意は同じ28px高とし、必須・1個選択など選択数を文で示す。選択肢の価格は基本価格への1個あたりの差額だと説明し、追加は薄い赤背景と赤の+、割引は薄い緑背景と緑の−で示す。注文画面の価格に(税込)を明記し、税区分の文字サイズ・太さ・ベースラインを金額へ揃え、参考外貨は文字を薄くして補助表示に保つ。有色の価格欄では税込・補助通貨へグレーを使わず、追加・割引に対応する赤・緑を継承し、補助通貨は同系色の濃淡で区別する。商品詳細とその選択肢にはイラスト注記を付けない。会話とヘッダーの操作は継続できる。注文確認は同じペイン内に表示する。Agentは公開カタログにある商品IDだけを指定し、価格・売切・選択肢はAPIのカタログから表示する。
カテゴリ列の左に虫眼鏡アイコンと検索ボタンを固定し、カテゴリ列だけを横スクロールする。検索はメニューペイン内の画面として開き、手動で開いた時だけ検索バーへ通信完了前にfocusする。音声から開いた時はfocusを移さない。IME変換中は実行せず、確定した入力の250ms後に検索する。空欄は全商品、0件は該当なしとし、更新中と失敗を区別する。失敗後も入力と直前の結果を残して再試行できる。

検索はAPIが返す関連度順の商品IDを8件ずつ表示し、件数と前後ページ操作を添える。売切商品も表示し、選択不可にする。通常の商品カード・価格・テーマを使い、戻る操作でカテゴリ一覧と検索ボタンのfocusへ戻る。検索語・ページは卓の`menuSearch`で共有し、商品詳細・カート・再読込で保持する。カタログ版が変われば検索語を保ち先頭ページから再計算する。画面遷移や音声からの条件変更は未送信の検索を取り消し、古い応答で新しい入力や画面を巻き戻さない。

選択タブは卓状態の `uiSection` として保存する。注文済みの `orders` とお会計の `bill` は互換性を維持し、画面では同じ履歴とお会計タブへ表示する。商品詳細は `selectedProductId` を共有し、`PATCH /api/table/ui` と `setUiSection` の `productId` で開閉する。別タブへの移動では詳細選択を解除する。GUIの `PATCH /api/table/ui` とAgentの `setUiSection` は同じ認可済み操作を使う。Agentは `getTableState` で現在のタブを読み、利用客の依頼に沿って切り替える。

GUIの未確定操作はTanStack QueryのMutation cacheへ保持し、Query cacheはAPIの確定値を所有する。カゴ・画面操作は卓単位のscopeで直列化し、送信開始時の最新確定版へ行IDと追加・編集・数量・削除の意図を適用する。数量・件数・商品画像・商品詳細の開閉・タブ・言語・話速は通信完了を待たず表示する。カゴへの追加では現在のタブ・カテゴリ・スクロールを維持し、一致する商品詳細だけをカゴ更新と同時に閉じる。別の画面更新を続けて送らない。

未確定行の価格をブラウザーで計算しない。金額はAPIの確定額と更新中の表示を使い、同期完了まで確認・送信を無効にする。他の商品操作は継続できる。失敗した操作だけを取り消し、カスタマイズ入力と再試行手段を残す。古い応答・409・通知で後続操作や新たに開いた詳細を巻き戻さない。注文送信・店員呼出・会計依頼の成功表示はAPI受理後に出す。
確認画面は商品・変更・数量・金額を省略しない。同じスナップショットを音声で読み、訂正とGUI確定の両方を提供する。
注文操作はメニュー・カゴとも下部タブ直上に固定し、注文を確定するから、確認中の修正と注文を送信するへ切り替える。確認中に別の無効な注文確認ボタンを残さない。
会話内の確認カードからも現行スナップショットのGUI確認を開ける。カード表示やタブ切替だけでは注文を確定しない。
音声が壊れても全画面エラーへせず、会話側に状態を出してGUI注文を継続する。

注文ペインの下端に、おしながき・注文かご・履歴とお会計の3つの切替タブを一列にまとめる。カゴアイコンとカゴ・履歴の数量を0件でも常に表示し、カゴには合計・数量・最大3枚の角丸四角形の32pxの商品画像、履歴とお会計にはAPIの注文済み合計を表示する。タブボタンは内部の縦paddingとgapを詰め、音声欄の下部ボタンと同じ56px高に揃える。中身は省略せず、既存の14pxを保ち、幅に応じた文字の縮小を行わない。円・参考通貨は一行に保ち、外貨を省略せず、狭幅でも円と同じ一行に表示する。カゴと履歴内に見出しとAPI由来の合計を表示する。メニューには追加の見出し・合計を置かず、商品一覧から始める。履歴内には注文済み合計を明示する。カゴ内と商品が入ったメニューでは、下部タブ直上の固定バーに注文を確定する・修正・注文を送信するを置き、内容の高さやスクロールで操作位置を変えない。商品画像stackはカード色の細い枠・浅い影・重なり幅で各画像を見分け、丸い数量表示との間に余白を置く。メニュータブはアイコンと文言を縦中央へ揃える。カードの外枠と操作・入力の境界には既存のborderトークンを使う。カスタマイズtag、選択行の強調、Dialog内部の区切りには余白と面を使い、罫線を重ねない。カテゴリ選択は共通Buttonのsecondary／outlineを使い、独自の押下色と境界色を持たせない。数量入力はinput・control-edge-hover・ringと浅い内側の影を使う。文字色を境界へ流用せず、罫線へ独自のコントラスト値を課さない。履歴は注文ごとの時刻・状態・合計を持つ罫線付きの明細とし、会計内訳は明細の後に置く。履歴のカスタマイズには現在カタログで取得できる選択肢画像を添え、名称・価格・数量は注文snapshotを維持する。

ヘッダーは全幅で64px高・横一行とし、国旗・店員呼出の文言を維持し、ゲーム・QR参加はアイコンで表示する。TableCastロゴは112px幅、店舗バナーは40px高を全幅で維持し、画面幅による縮小はしない。狭幅は呼出を右端へ残して他の項目をヘッダー内で横スクロールできるようにする。左上はTableCastロゴ・縦の区切り線・店舗バナー・店名と卓名の順に横一行で置く。両ロゴは現在の注文画面へのリンクとし、通常端末とplaygroundで同じ表示部品を使う。店員呼出を一番右上に置き、その左に言語と参考通貨を右寄せする。カゴ追加・更新、注文確定、店員呼出・会計依頼の成功は4秒のtoastで通知し、失敗は入力の近くに残す。追加操作時に商品写真をカゴアイコンへ280msの弧で放り込み、注文確定成功時にはカゴの画像を履歴タブへ順に運ぶ。履歴タブにも注文済みの商品画像を残す。動きを減らす設定とキーボード操作では移動を省略する。

## 店舗画面

店舗ホームは `/admin/stores/:storeId`、統計は `/admin/stores/:storeId/statistics`。通常のログイン・PWA起動・店舗切替はホームへ進む。明示したフロアURL、`/admin/live?section=live`、下書き・設定・履歴への旧リンクは維持する。

ホームは要対応→現在の営業→終了済み来店の集計→導入案内の順とする。呼出・会計待ち・音声異常はフロアの対応する絞込みへ進む。公開中の商品と有効な登録端末から準備状態を示し、未取得や失敗を未設定と混同しない。画像付きのプラグイン案内から既存の導入ページへ進める。OAuth接続の有無をプラグイン導入済みと扱わない。

統計はowner/adminだけが既存APIを取得する。今日・直近7日・30日・指定期間と概要・商品別・選択肢別をURLへ保持する。日付はJST、指定した終了日を含む。対象は期間内に閉卓した通常来店で、営業中の数値と混在させない。集計の基準時刻・取得時刻・欠損・取消等の除外・データの出所に関する制約を示す。

商品・選択肢の一覧は30項目ずつ取得し、続きの有無を表示する。グラフは取得済みの先頭10項目までを数量で示し、ID順を人気ランキングとして扱わない。全取得済み項目の数値表を併設し、失敗しても既存行・期間を維持して再試行できる。統計APIにない時系列を作らない。

請求の日別グラフと統計の数量グラフはTanStack Chartsを使う。キーボード・タッチの詳細表示と数値表を残し、数値更新の装飾的なアニメーションは使わない。サイドバーのMod+B、テーマ保存のMod+SはTanStack Hotkeysが管理する。Mod+Bは入力欄では動作せず、常に通常のボタンも使える。

`/admin/stores/:storeId/floor` に全卓のTanStack Tableを置く。旧 `/admin/live` は対象店舗のページへ転送する。上部の稼働卓・呼出・会計待ち・音声異常の集計から、対象の卓を絞り込める。`filter`は`all`・`attention`・`active`・`called`・`billing`・`voice`・`vacant`を扱い、URLに保持する。
一覧は卓・人数、状態、要対応、注文・会計の4列を中心にする。経過と客の言語は状態へ、未確定カート・注文済・未会計は注文・会計へまとめ、詳しい履歴・会話・診断は来店詳細へ置く。
優先順は要対応→会計待ち→音声異常→利用中→空席。並び順の頻繁な自動変更で操作中の行を飛ばさない。

一覧を初期表示として維持し、`view=timeline&date=YYYY-MM-DD`で卓別の日別タイムラインへ切り替える。日本時間の1日を横軸、実卓を縦軸にして、同卓の複数回来店と日跨ぎを開始・終了時刻から描く。卓名と時刻目盛はスクロール中も固定する。前日・翌日・日付入力・現在時刻への移動と卓検索を提供する。

上部集計は常に現在の状況と明記し、今日の利用中の来店にだけ店員呼出・会計待ち・音声異常を重ねる。過去の注意状態を推測しない。短い滞在・滞在時間0分も展開一覧の44px以上の操作から個別に詳細を開ける。今日の空席から既存の開卓画面へ進める。再取得時にスクロールやフォーカスを変更しない。

期間取得は1ページ100件で、続きがあれば一部の来店と明示する。取得失敗を来店なしへ変換せず、再試行と取得済みデータを保持する。日付と初期時刻はloaderからSSRへ引き継ぐ。詳細な期間・ページング・制約は[タイムライン設計](floor-timeline-design.md)を参照する。

卓の詳細は `/admin/stores/:storeId/visits/:sessionId` に表示する。概要・ログ・注文・会計・診断は `view` 検索値で再現する。詳細表示にDialogやSheetを使わない。フロアから開く場合は一覧の表示形式・日付・絞込みを保持し、詳細内のログや会計へ移動してからも同じ一覧へ戻れる。
提供・支払登録は権限を検証し、失敗を成功表示しない。診断IDやraw provider errorは通常の業務欄に出さない。
スタッフがEnglishにしても客の日本語セッションは変更しない。英語の業務イベント表示と、日本語原文の会話ログが共存できる。

過去の来店は履歴から参照する。店舗ごとに閉卓日時の新しい順で卓・人数・日時・会計総額を表示し、続きを読み込めるようにする。同時刻の来店も区別し、店舗変更後に前の店舗の履歴を残さない。
履歴から開く詳細では、保存済みの注文と会計、原文の会話・操作ログを表示する。古いログも遡れるようにし、初期表示に入力フォーム、提供・呼出解除・閉卓の操作を置かない。会計の訂正だけはスタッフが会計を調整から入力を開き、理由付きで記録する。来店を再開せず、ポイント配分の差分も反映する。

## 部品とStorybook

Base UIのDialog、Drawer、Radio Group、Checkbox、Number Field、Tabs、Alert Dialog等を必要な範囲で使う。見た目を揃える部品だけを `apps/web/src/components` に置き、全APIを包む独自UIライブラリは作らない。
Storybookは `apps/web/.storybook` と部品に隣接するStoryで十分。独立配布するUI製品でも複数Webアプリでもないため、`apps/storybook` を増やす理由はない。[S14](sources.md#s14)

日英、長い商品名、停止・再開、許可拒否、接続中、割込、エラー、確認失効、画像なし、売切、要対応卓をStoryで再現する。
Storyには実OpenAIを接続せず、同じ表示部品へ固定状態・操作を渡す。実際のマイク停止・再接続は統合試験で確認する。

### オブジェクトを起点にする表示

店舗・商品・カテゴリ・プラン・来店・下書きの一覧は、識別名を主リンクにして詳細へ進む。名前に属性と状態を添え、対象を選んでから編集・公開などの操作へ進む。店舗の設定・メンバーのように独立した行き先を持つ副操作は区別して残す。詳細と一覧を往復しても公開／下書きの対象とURLの検索条件を保持する。メニュー・店舗デザイン・変更確認をまたぐ場合も、ナビゲーションとヘッダーは同じ設定対象を表示する。

管理画面のPageHeaderはページ名・説明・状態・操作の配置を揃え、長い対象名や狭い幅では折り返す。表示の共通化に業務query・認可・routeを含めない。共通Buttonは通常48px以上、コンパクト操作44px以上の操作領域と内容に応じた高さを持ち、長い状態名を含むBadgeも文字を切らない。卓上の商品カードでは商品名と金額を16px以上とし、メニューペインが狭ければ一列へ戻す。

## 会話と音声操作の配置

横向きのタブレットでは会話・メニューを並べ、両ペインを独立スクロールにする。幅56rem未満は会話→メニューの縦並びにする。言語はヘッダーに常設する。停止／再開・音声設定・音声状態・48pxのorbと実波形は会話欄下端へ固定し、操作ボタンの虹色リングを保つ。`--voice-spectrum`は音声操作固有の意味トークンであり、通常操作の無彩色化対象に含めない。停止中・再開ボタンでも全周に保持し、独立した線や灰色の影へ置き換えない。カメラは左上のサイズ調整可能な映像枠と、その下に左寄せした操作列に分け、ソース比率を保つ。停止中も枠・波形の高さを保つ。話速は `speechSpeed`、既定1倍、範囲0.5〜1.5倍・0.1刻みで卓に保存し、音声Agentが2秒周期で同期して次のTTS contextに適用する。
会話は初期表示と逐次更新を自動追従し、履歴を上へスクロールしたら解除する。最新へ戻るボタンから再開できる。空の確定・中断吹き出しを表示せず、ツール結果は対象発話の近くに置く。話者情報のない発話はお客さまと表示し、内部識別子や診断文を表示しない。
カートと履歴は商品ごとのカードとし、商品名を主見出し、数量とAPI由来の行合計を属性としてまとめ、単価は重複表示しない。カスタマイズは項目名: 画像 選択値の順の44px以上で高さを揃えたタグとし、編集はアイコンと内容を変更のラベルを付け、数量・削除と同じ54px高の操作列へまとめる。カスタマイズtagと操作列は別の行にし、間に16pxの余白を置く。商品名・価格と属性の間は16px、写真と本文の間も16px、商品同士と選択グループ同士は24pxを取り、tagは内側8px・項目間8pxとし、操作列は右寄せ・ボタン間12pxで配置する。数量はラベルを入力枠内へ入れた数値入力と増減ボタンへ一か所にまとめ、カゴ・詳細・追加項目で数値幅40px・増減ボタン44px・同じ内側余白へ揃え、別の数量表示を重複させない。数量増減・削除の操作はカード内で右寄せし、削除はdestructive色、補助操作は枠付きボタンにする。商品画像はカード内の左上へ揃え、画像自体は元の比率で全体を収める。カートは商品画像・数量増減・オプション編集を備え、数量変更もAPIの版検査と価格計算を通す。

AgentのsetLanguageはGUIと同じ言語変更処理を使い、同じ音声sessionと声を保って会話・表示を切り替える。古い注文確認とturnは失効させ、カート・注文は維持する。言語別の声設定は次回接続から反映する。setSpeechSpeedはGUIと同じ範囲・刻みを検証し、次の発話へ適用する。
発話の話者は識別済み単語の多数決で決める。同数・全語未識別では話者を未設定とし、エラーにせず会話を続ける。

標準テーマは白とGrayの無彩色を基調に、主操作・音声操作はチャコールの面と白文字、通常の選択は無彩色の面と太さで示す。公開・正常はGreen、注意はAmber、危険・失敗はRed、情報はBlueの意味色を使い、文字と記号を併記する。ナビゲーションの所属色は業務状態色と分ける。色だけを装飾目的で増やさず、店舗独自色はStoreThemeの適用範囲へ閉じ込める。

色はRadix Colorsの原色スケールから意味別トークンを経由する。背景は1–2、操作面は3–5、境界は6–8、有彩色の塗りは9–10、文字は11–12を使う。部品から原色や直接色を指定せず、色付き部品と店舗独自色のhover・押下も同系色を保つ。主ボタンは浅いグラデーション、上辺の光、接地する影、押下の沈み込みを持ち、入力は浅い内側の影、静的な情報面とBadgeは落ち着いた面にする。純黒の1px境界線を使わず、境界・影・focusを別トークンで管理する。ガラス表現はシェルや浮いた操作面に限り、本文・表・入力には読みやすい下地を確保する。

音声orbはPaper ShadersのSmokeRingを使用し、状態間の形と流速をMotionで補間する。聞き取りは緩やかな波とマイク、思考は密な揺れと星、ツール実行は細い輪・破線と工具、発話は波の変形と音声記号で区別する。実音声の音量で半径、周波数の分布で波の細かさを変える。横の波形は実音声を示し、無音の思考や処理中は架空の音声波形を作らない。声かけ中にツールが動いていれば発話状態とツール実行表示を併記し、停止後の古いツールイベントを処理中と表示しない。

停止・エラー時は静止し、動きを減らす設定ではshaderと装飾アニメーションを停止する。画面が非表示の間はshaderと音声解析の描画更新も止める。状態は色や動きだけに依存せず、文字と記号でも伝える。カード・商品ページは補助であり、必要な選択肢や判断材料は音声でも伝える。

## 管理コンソールの表示基準

ナビゲーション・ユーザーメニューを左側、現在の作業と本文を右側へ配置する。組織・店舗切替はサイドバー上部の一箇所に置き、ページ見出しへ混ぜない。折りたたみ時も店舗アイコンから切替でき、狭い画面ではナビゲーション内で同じ切替を使う。サイドバーが見えない場合や折りたたみ中はshellのtoolbarに現在の店舗名だけを表示し、切替操作を重複させない。下書きの詳細をナビゲーションへ繰り返さない。狭い画面ではサイドバーを開閉する。店舗作成・招待・端末登録は個別ページへ移動する。

管理サイドバーは境界のつまみで幅を調整する。既定16rem、通常14〜24rem、折りたたみ時4.5remとし、ブラウザーに幅を保存する。矢印キーでも操作できる。主領域とサイドバーの一覧は画面内で独立してスクロールし、狭い画面では幅調整を外して従来の開閉ナビゲーションにする。共通の仕切りはshadcnと同じ`react-resizable-panels`を使い、寸法の制約・保存・キーボード操作を独自実装しない。

本文・入力・主操作は16px、補助情報は14px以上を基本とし、文字はforeground・muted-foregroundなどの意味別トークンで指定する。通常の操作と入力は48px、コンパクト操作は44px、客向け主操作は56px以上とする。余白は4px基準で、部品内4–8px、対象内12–16px、対象間24–32pxに揃える。白背景を基準にし、OSのダークモードで一部の入力だけが暗くならないようにする。選択状態は背景と太さで示し、キーボードフォーカスを明示する。

初期読込でもコンソール枠を維持し、スクロールバー領域を予約する。ユーザーは丸い画像または人物アイコン、名前、メールを一緒に表示する。メールは省略せず折り返す。欠損時は人物アイコンと短い代替文を使い、IDを表示名へ代用しない。客向けの同席者は人物アイコンと共有を許可した名前だけを表示し、メールは公開しない。Googleはロゴ、破壊的な操作は赤とアイコン、現在の端末はテキスト付きの印で識別する。

## 管理画面のページ構成

店舗=組織であり、店舗配下にメンバーと端末を置く。スタッフ・端末・商品などの比較一覧は共通DataTableとTanStack Tableを使う。フロアの一覧は卓名・滞在・要対応・伝票を一つの卓カードにまとめ、来店を開く操作は独立したボタンにする。選択前から現在の項目、日時、状態、操作を表示する。役割はアイコンと色のBadge、削除・取消はdestructiveの操作として区別する。

メニューは `/admin/stores/:storeId/menu/:section` の商品・カテゴリ・プラン・接客設定に分け、項目詳細は `/:itemId` に置く。現在の設定は閲覧用の表示と一覧で見せる。変更作成後は `/menu/changes/:draftId/:section/:itemId` で編集し、`/menu/changes/:draftId` で差分の検証と店舗への反映を行う。未保存の変更を残した移動は確認する。サイドバーは営業、メニュー・接客、会員施策、店舗管理、連携・店舗一覧の5分類にし、対象のページへ直接移動する。営業はホーム・統計・フロアと来店履歴、メニュー・接客は商品・カテゴリ・プラン・接客・店舗デザイン・ゲーム・変更管理、会員施策はポイントとクーポン、店舗管理はスタッフ・端末・店舗情報と、選択中の組織に属する課金・請求を扱う。課金・請求を店舗一覧などの全体管理リンクと並列に置かない。アカウントと外部接続は店舗の対象から分ける。ページ内に同じナビゲーションを重ねず、直接URLでも現在地を示す。下書き編集時の子ページは同じ下書き内を移動する。

接客設定は店舗ごとに1件のため、`/menu/cast` を概要画面にし、1行だけの一覧・検索・ページ操作を置かない。日英の接客方針と話す声は共通LanguageFieldsで1言語ずつ表示する。接客方針は本文内に全文を安全なMarkdownとして表示し、別ダイアログへ分断しない。音声は標準音声APIの名称・未設定・利用不可、自発的な声かけは言語共通のON/OFFと近接する短い影響説明で示す。保存済み音声が利用不可の場合は、既存の音声接続が標準のMarinを使うことを明示する。音声一覧の取得失敗を利用不可と混同せず再試行できる。言語切替は表示中の対象だけを変え、編集中の入力と保存形式を保持する。

概要の各項目から対応する接客方針・音声・声かけの入力へ移動してfocusする。公開中の概要では共通の下書き選択、編集中の概要では同じ下書きを使い、変更確認・明示公開後は接客概要へ戻る。公開済み・破棄済み下書きの概要はAPIの状態を示して編集入口を出さない。接客設定の編集部品、公開操作、共通フォーム配置は他の設定画面と共用する。

商品詳細は写真・名前・価格・販売状態を先頭に置き、公開中の内容を理解してから編集へ進める。編集では基本情報、カスタマイズ、翻訳・接客説明のまとまりを分け、IDやタグなどの管理情報は補助詳細へ置く。公開中の店舗デザインは注文画面の表示プレビューと設定概要を使い、無効化した編集フォームを閲覧画面にしない。下書きのデザインだけを編集できる。

商品一覧は画像・名前・カテゴリ・価格・販売状態を表示し、日英の名前・読み・別名・カテゴリ名・説明文を、[音声と共通の正規化・誤字脱字・関連度順](product.md#商品カスタマイズ)で検索できる。カテゴリ・プラン一覧も同じ検索処理を使う。カテゴリと販売状態の絞り込み、検索語、ページ位置はURLの`q`・`category`・`availability`・`page`に保持し、詳細・下書き編集・公開確認・公開後の一覧へ引き継ぐ。店舗切替では別店舗の条件や入力を引き継がない。カテゴリには所属商品数と商品名、プランには価格・利用時間・ラストオーダー・指定対象の概要を表示する。初回読込、通信失敗、未登録、条件に一致しない0件を区別し、再取得に失敗しても取得済みの一覧を残す。

設定の編集開始では再開する下書きと新規作成をダイアログで選ぶ。再開候補は編集中・検証済みの下書きだけを更新時刻順に30件ずつ取得し、作成元公開版、下書き更新番号、変更対象と現在公開版からの差分件数を表示する。続きはカーソルで読み込み、候補一覧へ全設定・差分本文を返さない。MCPと既存履歴一覧のAPIは維持する。

店舗名はサイドバーの店舗切替へ置く。メニュー・接客・デザイン・変更確認・履歴はConfigurationHeaderを共用し、表示対象の選択、公開版、作成元、保存済み下書きの状態、差分件数を常設する。下書きは短縮IDやハッシュでなく状態・日時で識別する。本文のPageHeaderに同じ状態Badgeや公開／編集中の案内を繰り返さない。

フォームが入力・mutationを所有し、ConfigurationToolbarから保存状態と必要な操作だけを共通ヘッダーの所定位置へ描画する。未保存・保存中・失敗・競合は公開可否と分け、保存・変更確認・検証・公開を同じ場所から行えるようにする。キャスト概要の変更確認もここへ置く。SSR時も操作領域を予約し、狭幅の常設ヘッダーを長い説明で埋めない。料金変更の注意や検証結果の詳細は対象の差分の直前へ短く置く。

表示対象を切り替えても存在する商品・カテゴリ等を維持し、対象がなければ一覧へ戻る。未保存の移動を取り消した場合は入力と対象を保持する。URL・既存Queryを正本とし、下書きIDが残る場合もAPIのstatusから操作可否を決める。公開済み・破棄済みは閲覧専用とし、店舗を切り替えたときは以前のフォーム状態を引き継がない。

保存後は変更確認・検証へ進み、検証エラーのある設定へ戻れる。公開は変更内容・反映対象・タイミングを確認するダイアログの明示操作で行う。公開時は利用中の卓を含むメニューが更新され、未確定の注文確認は失効する。確定済み注文金額と適用中のプラン条件は維持する。公開後は公開中の各設定へ戻れる。作成元より公開版が進んでいる場合は公開不可と入力保持を示し、別の下書きを作成できる公開画面へ案内する。

未保存入力を戻す操作は最後に保存した値へ戻し、下書き全体の破棄とは別に確認する。保存失敗・競合では入力を保持し、同じ保存操作を再試行できる。下書き更新番号の競合では、未保存入力を破棄することを確認した後だけ最新の保存済み下書きを読み込む。ページ離脱と再読み込みの未保存保護を維持する。

管理者の商品編集では、選択肢ごとに画像参照と写真・イメージの種別を設定し、プレビューと既存の日英説明欄で確認する。商品詳細の選択肢一覧にも同じ画像と説明を表示する。変更は既存の下書き保存・検証・人間の公開承認を経て客向けに反映する。

商品と選択肢の画像入力は共通部品を使い、ファイル選択と既存画像指定を分ける。通常はPNG・JPEG・WebPの5 MB以内・1,600万画素以内を取り込み、現在の編集画像と選択候補を別々に確認する。既存参照の直接指定は上級設定に置き、`tablecast/menu/photo.webp`のような保存済み参照であり端末のファイルパスではないことを説明する。取込には出所と生成画像の申告を必要とし、生成画像の種別はイメージにする。店舗所有・存在・種別・出所は既存APIが検証する。

画像の取込成功時だけ編集参照を置き換える。取込中・再試行・形式や容量のエラーを日英で案内し、失敗しても元の画像参照・選択ファイル・他の入力を保持する。画像なしと読込失敗を区別し、置換と解除をキーボードでも操作できる。取込・置換・解除と下書き保存・明示公開は別操作として説明し、画像部品から保存や公開を実行しない。

商品・選択肢の取込中は、同じ店舗の全画像取込が完了するまで親フォームの保存・削除・画面移動を止める。ブラウザー終了時には未保存内容と同様に確認し、PWA更新も待機する。React Queryの店舗別mutation keyで複数画像の進行を集計し、操作時点のpendingを確認する。取込後は画像を含む最新の入力を下書き保存する。

取込前の選択候補や未適用の画像入力も未保存として扱い、取込失敗後も離脱確認とPWA更新の待機を維持する。画像の入力を戻す操作で候補と未適用入力だけを破棄できる。画像解除と別ファイルの選択では、元画像の種別・生成申告・出所を引き継がず再入力を求める。同じファイルの再試行では入力を保持する。

店舗アイコンは `/admin/stores/:storeId/profile` で管理者が設定する。組織の`logo`を正本とし、店舗一覧・切替・設定ページでは角丸の正方形、ユーザー画像は丸形にする。PNG・JPEG・WebPの1MB以内を受け付け、ユーザー画像と同じ検証・R2保存経路を使う。

MCP・Skillsの管理はプラグイン導入、手動導入、OAuth接続に分け、各ページをURLで再現する。店舗の利用者へ公開HTTPS MCPとOAuthの接続を案内し、cloneやローカル開発環境を要求しない。公式ガイド、公開pluginと同じ本番接続URL、CLI設定のコピー、同梱SKILL.mdの任意ダウンロードを用意する。接続URLは`plugins/tablecast/.mcp.json`を参照し、表示用に複製しない。OAuth接続一覧はアプリ・店舗・scope・状態・承認日時・更新日時・アクセストークン期限・更新トークン期限・解除操作をTanStack Tableで表示する。

## 初期表示と非同期状態

初期データはroute loaderで取得し、SSRとブラウザーで同じqueryOptionsを使う。遷移待ちは寸法を予約したSkeleton、失敗は再試行可能なerror boundary、取得成功時の空配列は0件として表示する。更新に失敗しても取得済みデータを残し、失敗を空の結果へ変換しない。短いopacityの出現アニメーションとSkeletonのpulseは`prefers-reduced-motion`に従う。

JSが必要なボタンと入力はTanStackの`useHydrated`で操作可能になる時点を揃える。SSRの見た目だけが先に届いた状態で、入力や注文操作を取りこぼさない。金額の円記号はICUによる全角・半角の差を正規化する。フロアの経過時間の初期値にはSSR queryの取得時刻を使う。

ペイン幅は`tablecast-layout-`から始まるCookieへ保存し、SSRでも同じ幅を描く。Cookieから画面へ渡すのはこの表示設定だけで、認証Cookieは含めない。以前のlocalStorageだけに保存された幅は初回に既定幅となる。表示設定の破損は既定幅へ戻し、画面を停止させない。

商品と選択肢の画像はUnpicの`srcset`・`sizes`と幅・高さを持ち、R2/Imagesから必要な大きさのWebPを取得する。配信幅は1〜1600px、未指定時は640px。幅ごとのETagが一致するときは画像を再変換しない。音声停止中は同じ高さの静的表示を使い、波形・WebRTC接続のコードは音声の開始時に読み込む。

商品一覧は画像の有無にかかわらず正方形の画像領域を予約する。未登録、取得待ち、取得失敗、再取得によって商品名・価格や次の行の位置を動かさない。画像未登録だけを文字と小さなアイコンへ縮めない。

`ProductImage`は取込時に生成したBlurHashを`@unpic/placeholder`で長辺16px・元画像と同じ縦横比のdata URLへ復元し、SSRのplaceholder層へ埋め込む。復元は同じhashと寸法でmemo化し、追加のplaceholder HTTP通信は行わない。実寸・BlurHashの正本はD1とし、設定JSONへ複製しない。カタログと個別下書きのHTTP応答に`imageAssets`をまとめて返し、店舗・卓・デモごとの`ImageProvider`が配信URLと表示情報を既存部品へ接続する。SSR時に画像本体を解析せず、画像ごとの追加DB取得もしない。

取込は既存Images bindingで長辺32px以内のPNGへ縮小し、`@unpic/pixels`と`blurhash.encode(..., 6, 4)`を使う。独自decoder・チャンネル変換・成分数の自動調整は持たない。商品・選択肢・ロゴ・バナーを既存の`ProductImage`へ揃え、バナーは保存実寸から縦横比を予約する。

Unpic 1.0.2の`unstyled`は`background`の生成も無効にするため、共通の画像枠とplaceholder層へCSS変数を渡す。placeholderだけにCSS blur 4pxをかけ、本画像のdecode後に既存motion tokenの200ms・ease-outでopacityを消す。本画像の取得と描画は演出の完了待ちにしない。キャッシュ済み・hydration前の完了・失敗・reduced motionでは即時に背景を消し、透過部分に残さない。読込前のWebKitを完了・失敗と誤認しないよう、`complete`と併せて`currentSrc`の選択済みを確認する。`layout="fixed"`でHTMLの幅・高さを残し、CSSの縦横比と各呼出し側の枠で読込待ち・失敗時の寸法を維持する。画像なしの表示は各呼出し側が所有する。

遅延読込では`sizes="auto, …"`で可変ペイン内の実幅を使う。客画面のfallbackはPanelの実幅とコンテナに応じた1〜3列から求め、固定の50%ペインには依存しない。カートは112px、通常の選択肢は96px、縮小表示は32px、商品詳細は枠に合わせて128/160pxとする。幅候補は元画像幅と1600pxを超えず、固定枠ではDPR 1〜3の候補へ絞る。DPRとブラウザーの取得幅は既存性能試験で確認する。

変換結果はCloudflare Cache APIの`tablecast-images-v1`へ保存する。配信はWebP品質85を明示し、URLへ`v=2`を付ける。キャッシュキーとETagは元画像の版・幅・形式・品質・変換版を含み、未知のqueryは含めない。変換設定を変える場合は配信URLと内部キーの変換版を更新し、保存済みの別版を一括削除しない。固定キーでもR2で現在のETagを確認してから再利用するため、差替え・削除に追従する。ブラウザーにはハッシュキーのみimmutable、固定キーにはno-cacheを返す。`X-Tablecast-Image-Cache`のHIT/MISSで変換の省略を観測でき、304はその前に判定する。Cache APIの保存はデータセンター単位であり、localテストの成功を実配信のhit率の保証にしない。 実測値と再現条件は[画像の検証記録](image-performance.md)を参照する。

### 設定フォームの配置

商品・カテゴリ・プラン・接客設定・店舗プロフィールは、ページ見出し、セクション、反復行、項目の順に階層を揃える。基本情報、価格・販売状態、名称・翻訳、画像、安全情報、カスタマイズ、プランの制限・対象を意味ごとに分ける。セクションは見出しと24px以上の余白、内部は16〜20pxの間隔を基本とし、一律の罫線や枠の入れ子を増やさない。ページはh1、セクションはh2、グループはh3、選択肢はh4とする。

フォームの列数は画面幅ではなくコンテンツ領域のcontainer queryで切り替える。sidebarの幅変更・iPad縦横で入力領域が狭くなった場合は一列に戻し、ラベルを折り返す。チェックボックスの文言はチェックと横に並べ、祖先要素から全ラベルの配置を上書きしない。

反復行は通し番号と名称を常に表示し、選択方式・選択数・追加料金・最大数量・販売状態を同じ順序で比較できるようにする。長文の翻訳、画像、組合せ条件は標準detailsで展開する。入力は折畳み中も保持し、保存時に必須項目が不正なら該当する詳細を開いてフォーカスする。行と入力のDOMは安定したIDをkeyにし、追加後は新しい行見出し、削除後は隣の行見出しへフォーカスを移す。同名行でも対象グループ・選択肢・言語・項目をaria-labelledbyで区別する。

Lucideは追加にPlus、削除・破棄にTrash2、保存にSave、公開にUpload、履歴にHistory、画像にImageまたはImagePlus、戻る操作にArrowLeftを使う。主要操作はアイコンと文言を併記し、装飾アイコンはaria-hiddenにする。アイコンのみの操作には既存Tooltipとaccessible nameを用い、タッチでも操作の意味を確認できる説明を残す。展開操作は44px以上のタップ領域とフォーカス表示を持つ。公開・破棄・履歴の動作と位置は共通の変更管理を使い、各フォームへ複製しない。

現在の画像入力は商品では画像セクション、選択肢ではその行の詳細内、店舗ではプロフィールの画像セクションへ置く。画像選択・置換・解除の内部操作を変更しても、この対象とラベルの対応を維持する。

### アカウントと認証の配置

アカウントはプロフィール・接続済みアカウント・パスキー・ログイン端末の目次から該当する設定へ移動する。目次移動でフォームを作り直さず、未保存の入力を保持する。広い本文では目次を左側、狭い本文では折り返した上部の導線にする。外部連携は接続手順と接続先を先に表示し、利用例と権限説明を後に置く。

ログイン・旧登録・旧パスワード再設定URLは同じパスワードレス認証レイアウトを使い、店舗運営用のナビゲーションを置かない。上部にブランドと言語、本文にそのページの目的とフォーム、下部に登録・ログイン等の副導線を配置する。戻り先、OAuth、メール確認、失敗時の入力保持を維持する。

### フォームと操作結果

ログインリンク送信、店舗作成、招待、プロフィール・パスキー名、端末登録、開卓、会計入力はTanStack Formで入力・validation・送信状態を管理する。項目エラーはBase UI Fieldによりラベルと説明へ関連付け、`aria-invalid`・`aria-describedby`で取得できる。日英の修正案を表示し、失敗しても入力を保持する。送信中は主ボタンを無効化し、支援技術にも送信中を伝える。

保存・送信結果は寸法を確保した共通表示で切り替える。Motionの入場は200msでopacity・transformを使い、新しい状態を古い状態の退場待ちで遅らせない。処理中から失敗・成功へ即時に意味と操作を更新する。フォームの入力・フォーカスは切替中も維持する。

動きは`styles.css`の意味別時間トークンと`components/ui/motion-variants.ts`を共用し、押下120ms、hover150ms、Menu・Popover・Select180ms、Dialog・Drawer220ms、タブ・開閉・結果200msとする。Base UIの入退場属性を使い、途中反転できるCSS transitionを優先する。focusの輪郭は遷移させず、overlayにblurを付けない。タブは同時に二つのpanelをレイアウトへ残さず、`keepMounted`の入力とUndoを保つ。

実データ・編集欄の開閉は共通`Disclosure`を使う。非表示の必須入力がinvalidになった場合は祖先を開き、対象の入力へfocusを移す。補助説明だけを折りたたむ用途には使わない。カートの数量・追加・注文完了と保存・検証・公開状態の変化に短いフィードバックを付ける。表・統計の行や数値、頻繁なページ遷移には装飾的な移動を加えない。

`prefers-reduced-motion`では移動・拡縮・反復とCSS transitionを止め、操作・選択・結果は即時に利用できる。音声可視化の通常色は無彩色、エラーだけ危険色とし、Canvasとshaderへ同じ意味別トークンを渡す。停止・非表示では音声解析の描画更新も止める。

全画面の適用対象と維持する状態は[動きの適用範囲](ui-motion-audit.md)を参照する。

## 卓上ゲーム

卓上ゲームは客画面のゲームボタンから開き、開始前に音声を停止する。終了操作を本体側へ常設し、カートを維持して注文画面へ戻す。管理者は店舗のゲーム画面で版を選び、検証・試遊・明示承認付き公開・公開停止・旧版再公開を行う。[ゲーム仕様](game-plugins.md)を参照する。

## iPadのホーム画面アプリ

客向け `/` と店側 `/admin/live` は別のmanifest ID・起動先を持つ。Safariの共有からホーム画面に追加し、追加したアプリ内で端末登録またはログインする。双方を別アイコンとして追加でき、縦横の向きを固定しない。追加方法は画面末尾で日英表示し、standaloneでは隠す。

Web更新は起動・前景復帰・通信復帰と前景中60秒ごとに確認する。接客中の卓、端末登録の承認待ち、未保存フォーム、mutation・画面遷移中は適用しない。同じService Worker配下の全画面が応答して安全な場合のみ、短時間操作を止めて有効化・再読み込みする。応答なし・休止中の画面があれば待機し、次回復帰・起動時に再確認する。

オフラインでは取得済みの画像を再利用する。新規起動・ページ移動に失敗した場合は日英の復帰案内を表示する。注文・音声・認証はオンラインを必須とし、送信予約やAPI応答の永続キャッシュは持たない。

### 選択肢の条件編集

選択肢の詳細に要求条件と禁止条件を分けて置く。AND・ORは子を維持したまま切り替え、NOTは式全体を包む。子の削除で一子になったグループは自動的に平坦化せず、構造エラーを表示する。追加した節へフォーカスを移し、削除後は追加操作へ戻す。商品合計1,024節・設定合計65,536節を超える場合は、保存前に対象の上限と条件削減を日英で案内し、条件欄を開いてフォーカスする。

参照候補は同じ商品のグループ名・選択肢名・IDを表示し、日英の名称で検索できる。自己参照は選択不可、売切は明示し、参照切れは消さずエラーとして残す。式の自然言語要約を日英で表示する。数量グループの選択例は各選択肢の数量を1〜20で指定でき、設定上限を超えた例も試せる。試行は管理APIへ入力中の商品と数量を含む選択集合を送り、保存・公開なしで各節の真偽と数量等の選択制約エラーを表示する。プラン適用は試行の対象外とし、実注文時にAPIが判定する。式や選択を変えたら以前の試行結果を表示しない。

客画面は条件不足の行を編集でき、ORを全件必須へ変換せず式を表示する。自由文入力やブラウザー独自の条件評価を追加しない。

### 接客方針の編集

接客プロンプトは1. TableCastシステムと2. 店舗の2層に分ける。標準側は本文を操作なしで閲覧できる読取専用表示とし、通常は変更しないことと店舗側の設定先を近接表示する。日英それぞれの非推奨上書きを明示チェックで有効化し、解除するとその言語だけ標準へ戻す。ツール説明とモデル別役割・言語・認可条件は実行時に追加されることを伝える。標準の上書きも既存の下書き・差分・公開・履歴に含める。

接客方針はMarkdownを直接入力・貼付けし、同じ場所のプレビューへ切り替えて確認する。入力欄は内容に応じて伸び、縦にリサイズできる。言語はlocale配列に基づくタブで1言語ずつ広く表示し、切替時も未保存内容を保持する。接客方針・話す声・言語共通の自発的な声かけを区分する。HTMLや画像をプレビューで実行・取得しない。保存は書式と改行を含む本文投影で5,000 UTF-16単位まで。超過入力は消さず、保存を止める。既存の構造化文書は開く・切替・プレビューだけでは変換せず、編集した言語だけMarkdown文字列にする。保存待機・読取専用時は入力を止め、失敗時は保持する。保存形式・互換性は[接客エディター設計](prompt-editor-design.md)を参照する。

## 客向け会員アプリ

`/member`は店舗会員証の一覧、`/member/$storeId`は店舗会員証と同意設定を表示する。管理用サイドバーを使わず、スマホで読める一列の画面にする。初回は同行記録共有・来店中の記憶利用・自動保存を説明して同意を受け、次回のQR参加では追加操作を挟まない。会員用manifestの起動先は`/member`とし、アプリ画面と個人APIはオフライン保存しない。

店舗ホームは店舗名と会員状態、ポイント残高と保有券、現在または直近の来店の順に並べる。機能名だけの同格カードを入口にせず、残高から明細へ、券名と状態から券・交換特典へ進める。券一覧はページ単位の取得なので、未取得分を含む総数や利用可能枚数を推測しない。記憶と飲食記録は来店の下の副導線に置き、店舗別の設定と退会確認は折りたたむ。明細・記憶・券・来店の詳細には店舗名と会員証への戻り先を残す。

店舗会員の有効性を親ルートの`beforeLoad`で確認し、同意前にポイント・券・来店などの個人データを取得しない。有効な会員のホームは既存のポイント・券・来店Queryを並列取得し、一部の失敗でほかの取得済み情報を隠さない。店舗切替では店舗に属する入力・確認・mutation状態を引き継がない。設定保存と退会は既存のrevision・確認・失敗時入力保持を維持する。

## 店舗デザイン

`/admin/stores/{storeId}/design`から公開設定を確認し、既存の下書きを選択して店舗ロゴ・テーマ・チラシを編集する。店舗ロゴは`branding.logo`として画像キー・日英の代替テキスト・出所を保持し、組織共通アイコンを上書きしない。ヘッダー用の横長画像は`branding.banner`へ別に登録し、比率・透明部分を保って表示する。テーマ未設定時は従来表示を維持する。

`appearance`は色・見出し/本文書体・部品装飾・画像・追加CSSを持つ。登録画像は背景や下地へ配置できる。ヘッダー・音声・注文確認の構造と操作領域はテーマで変更しない。メニューには余白と部品の見た目の変更を許可する。フォントは端末標準のゴシック・明朝・丸ゴシックとfallbackを使い、外部フォントのuploadは初版対象外。CSSはAPIで構文解析し、公開部品の単一セレクタと許可した宣言だけを受け付ける。位置・非表示・任意URL・@規則・!importantは拒否する。

チラシは`banners`の配列順で表示し、画像内の複数領域から通常の商品詳細へ進む。各領域は安定ID・商品ID・0〜1の比率座標を持つ。画像は切り抜かず拡縮し、商品リンク一覧も表示する。画像失敗時は一覧を保持し、売切れ商品の選択は通常メニューと同じく無効にする。自動スライドと予約公開は含めない。

保存して注文画面で確認から、下書きを読み込んだ既存の会話注文デモを開く。日英、端末寸法・向き、商品詳細、音声操作を確認できる。公開は既存の差分確認画面で行う。画像の取込や下書き保存だけでは客側を変更しない。

画像の配置は`appearance.composition`へ保存する。`masthead`でメニュー上部に店舗ロゴとHTMLの店名を配置し、幅120〜360px・高さ40〜160px・余白0〜32pxと左右/中央揃えを指定する。ヘッダーのロゴ枠は固定で変えない。`banners`は1/2列と間隔8〜32pxを選び、個別チラシの`span: full`で全幅を使う。メニュー領域が狭い場合は1列に戻す。チラシ画像の切抜きや操作ラベルの画像化はしない。部品`menu-masthead`・`banner`にも装飾を指定できる。

単発の背景素材は`image.widthPercent`で部品に対する幅10〜200%、反復素材は`image.tileSize`でタイル幅32〜1024pxを指定する。省略時は既存fit/原寸を維持する。生成素材を使った[ラーメン店作例](design/themes/gomen/SOURCES.md)を実注文プレビューで検証する。

## stagingの評価用入口

stagingの未接続トップは、製品概要、佐藤晴香の模擬ログイン、会話注文デモの試し方を日英で案内する。開始ボタンは既存ログインの`returnTo`で京料理こもれびの会話注文デモへ進む。個人のGoogleアカウントやパスワードは不要であること、共有アカウントの設定を変更しないことを説明する。

音声開始・マイク許可・おすすめの相談・画面操作・注文確認の順を示し、実営業や実決済とは分離されたデモであることを伝える。店側のフロアへの入口も設ける。端末接続は折りたたみ内から利用でき、接続済みの客画面と本番の端末接続画面は従来どおりとする。

会員ホームは残高と保有券を一つの控えめなsurfaceへまとめ、来店は対象ごとの余白と見出しで示す。機能リンクや節を一律の罫線で区切らず、補助導線と設定を主情報から離して配置する。

画面のまとまりは対象ごとの見出し・余白・既存surfaceで表す。項目や節を一律の罫線で区切らない。境界線が必要な表・入力・操作領域は既存のborderトークンを使い、文字色の黒を境界線へ流用しない。文字200%試験は受入対象から除外する。

## 課金・請求

sidebarの管理グループから`/billing/$organizationId`へ開く。URLの組織を対象とし、組織切替で対象月・卓名/来店ID検索・ページを初期化する。APIとQuery keyも組織ごとに分ける。owner/adminには現在のプラン、請求期間と次回予定日、当期のAI利用料を先に表示する。無料プランではGUIのメニュー・注文・店舗管理を利用でき、AI音声接客は有料のスタンダードで利用できることを示す。両プランの比較と、無料への変更・解約をStripeで確定する導線を置き、期間末の最終精算と無料GUIの継続を説明する。

月別集計は現在の請求期間から分け、日別チャート・数値表と音声接客時間を示す。情報処理の回数は会話回数と区別して説明し、tokenは読み込み/生成した文章量の詳細へ置く。memberには利用量と明細だけ、owner/adminには料金のチャート・20件ずつの請求履歴も表示する。通常時にAIの準備完了通知を置かず、現在のプランから使える機能を説明する。AIの準備中・準備失敗では音声接客を開始できないこととGUIの継続利用を案内し、無料プランの管理者へAI設定通知を出さない。原価・為替・倍率・鍵は顧客へ表示しない。月次利用量はUTCの半開区間で集計し、画面へUTCを明示する。詳細は [課金・請求](billing.md) を参照する。

## 客画面の鏡表示と補助操作

会話ペインにソース比率を保つサイズ調整可能な鏡表示枠とON/OFF操作を常設し、明示ONした場合だけ端末内へ映像を表示する。カメラをダイアログへ移さず、OFF・許可待ち・エラーでも同じ枠を保つ。認可済みtoolから必要時に静止画像を1枚送信し、連続映像の送信・録画・画像保存は行わない。OFF・画面非表示・離脱で全trackを解放し、復帰しても自動再開しない。音声の停止・再開とは独立する。音声状態の表示はlive regionにせず、自動読み上げをしない。

店舗デザインの保存はボタンとTanStack HotkeysのMod+Sを使う。保存中・画像取込中・未反映の詳細入力がある場合はどちらも保存を抑止する。検証エラーは日英の項目名と説明で示し、要約へfocusを移す。

### 公開履歴と過去版の利用

`/admin/stores/{storeId}/menu/history`では公開版と保存済み下書きを新しい順に30件ずつ表示する。公開版の流れと下書きの派生を線で補助し、現在公開中・以前の公開版・下書きの状態・基準の公開版・復元元も文字で示す。線や色だけで関係を伝えず、通常のリスト・リンク・ボタンをキーボードで辿れるようにする。履歴と詳細はowner/adminだけが取得する。

公開版の選択をURLの`version`へ保持し、詳細パネルでは保存内容と現在公開中との差分を既存の変更確認部品で表示する。過去の内容を使う操作は、対象版・現在版・商品・価格・接客・デザインの範囲を説明してから新しい下書きを作る。作成だけでは公開しない。通常の変更確認・検証・明示公開へ進み、公開後も過去版と確定済み注文のsnapshotを保持する。競合時は詳細を保って現在版の読み直しを案内し、再確認してから作成する。再送は同じ下書きIDで収束させる。

公開履歴と破棄済み下書きに自動削除期限は設けていない。破棄済み下書きは閲覧のみとし、過去の公開版だけを復元元にできる。下書きの編集前の各入力を保存する機能ではない。旧データの公開元下書き・復元元は推測で補完せず、保存された情報だけを示す。snapshotが欠ける場合や現行schemaで読めない場合は復元しない。公開前の業務検証は通常の経路で必ず実行する。

[Substackの版選択と復元操作](https://mobbin.com/screens/b9578385-f96c-45a2-b2e2-483bfc410cb6)を参考に、履歴一覧から詳細の比較と復元確認へ進む構成にした。下書きの由来はGitの履歴図を参考に補助線と明示ラベルで示す。

### 人物・日時・操作の表示

日時は共通のDateTimeとcalendarDateで言語に自然な完全形を表示する。日本語は2026年10月20日(火) 14:30、英語はTuesday, 20 October 2026, 14:30とし、年・曜日を含める。月単位の集計は年月、時刻目盛は時刻の単位で表示し、日付のあるtooltipと表は完全形にする。日付はハイフンやJSTの接尾辞を付けない。入力値・URL・time要素のdateTime属性の機械形式は維持する。請求集計の世界標準時基準は説明文で明示する。

modal/drawerのoverlayは半透明の暗幕だけを使い、背景をぼかさない。iPadのホーム画面へ追加する案内は共通shellへ出さない。アプリ更新とオフラインの既存動作は維持する。

公開履歴は公開版の縦の流れと下書きの派生を形で区別する。内部ID・短縮ハッシュを表示名にせず、対象名・作成日時・公開版で識別する。保持期間などの補足は対象の日時や操作の直近へ短く置く。

### 補助説明・組版・言語表示

- 補助説明は対象の見出し・値・入力・操作の直近へ短く置く。説明だけのアコーディオンや末尾の注意事項一覧は使わない。編集する対象そのものや任意の詳細データの開閉とは区別する。
- 表の名称は左、金額・件数は見出しと値をともに右へ揃える。DataTableの数値列は`meta.align: "right"`を使う。
- 店舗ホームは現在の要対応と営業中の卓をまとめ、終了済み来店の集計から分離する。集計を主領域、導入・接続を補助領域とし、内容幅が狭い場合は縦に並べる。
- 言語はLanguageLabelでflag-iconsと日本語／Englishを併記する。国旗の素材と描画は通貨セレクタと共通のFlagを使う。旗は装飾で、国籍や人物属性を示す用途には使わない。言語を切り替える場合は日英と現在言語をタブに置き、日英以外の対応言語をドロップダウンから選ぶLanguageSwitch、来店の接客言語を選ぶ場合はラジオグループを使う。

月選択はBase UIのPopover内で年と月を選び、表示名・操作名をアプリの言語に合わせる。日付入力は共通DatePicker、日時入力はDateTimePickerを使い、フォームはTanStack FormのDateFieldへ接続する。OSのdate/datetime-local pickerを製品の表示UIに使わない。入力の表示は完全な自然日付、保存値は既存のISO形式を保つ。期間・日時のフォームは実コンテナ幅に合わせて列数を変え、日付の最低表示幅を確保する。カレンダー操作は44pxを保ち、日付全体が収まらない幅だけ次行へ移す。直接入力は日本語の年月日とISO、英語の完全な月名または日/月/年を受け付け、不正な日付や時刻を翌月・翌日へ繰り上げない。Base UI Popover内のカレンダーは44pxの操作領域、選択日へのfocus、矢印・Home/End・PageUp/Down・Shift+PageUp/Downを提供する。Escapeと選択後は入力へfocusを戻す。required/min/maxと入力refを保ち、日時の時刻は24時間表記で入力する。日付のクリア後も必須検証を維持し、日時の途中入力で他方の入力を消さない。言語切替でも未完成の入力を保持する。入力中からnative validityを更新し、エラー文は送信の検証時に表示してblur直後の操作を移動させない。MCP・Skillsの導入案内は固定内容をそのまま表示し、架空の一覧skeletonを挟まない。デモの取得中も同じtoolbar・端末枠・会話とメニューの領域を確保する。

サイドバーは営業（青）、メニュー・接客（紫）、会員施策（ローズ）、店舗管理（ティール）、連携・店舗一覧（水色）に分類する。色は所属を示し、業務の正常・要対応の意味とは分ける。アカウントは下部の人物メニューへ集約する。各グループと全体の開閉、最後に選択した店舗は利用者別の表示Cookieで保持し、SSRにも同じ設定を渡す。MCP・Skillsなど店舗URL外の画面でも選択を維持し、表示候補は認可済み店舗一覧から求める。初期表示は全グループを開き、利用者が選んだ開閉状態を優先する。店舗切替のsetActive操作は共通シェルに置き、成功後に認証キャッシュのactiveOrganizationIdも更新する。

### 一覧の操作とタブの共通表示

- データ一覧はCollectionToolbarに検索・絞り込み・並べ替えを分け、各領域と対象をアイコンとラベルで示す。検索欄には対象が分かる日英placeholderを置く。Base UIの選択で意味のある列と昇順・降順を指定し、名前は表示名、金額・数量・日時は元の値で並べる。内部IDや整形済み文字列をソート値にしない。検索語・絞り込み・並べ替え・ページはRouterのquery paramへ同期し、再読込と戻る操作で復元する。同一ページの複数一覧はキーを分け、OAuthの署名付きqueryは元のエンコードを保つ。条件リセットを同じ領域に置き、解除対象がなければ無効にする。リセットは対象一覧の条件とページだけを戻し、表示形式・店舗・他一覧を変更しない。DataTableは同じtoolbarを使い、cursorによる部分取得では検索・並べ替えが取得済み範囲であると近接表示する。
- タブは共通UI/Tabsを使い、選択面と操作面の光・影・境界・44px以上の操作領域を揃える。独自の下線だけのタブへ戻さない。言語入力等のkeepMounted契約と客向けテーマの適用範囲を保つ。
- フロアは表示形式を独立したラベル付きタブにし、検索・卓の状態条件・並べ替えをその下へ置く。タイムラインは通常64pxの行とし、卓名列と利用履歴の操作列は透明な面で時間軸スクロールの外に置く。列幅は狭幅で56px/48px、それ以外で80px/56pxとし、卓名だけを2行以内に表示する。状態色・利用時間・人数・未会計額は実時間幅のバーへ集め、hover・focus・クリックで利用内容を示す。現在の同じ利用IDから取得した言語は小さな旗と名前、時間制は砂時計と残り時間、制限なしは∞で区別する。プラン終了時刻・ラストオーダーは詳細と一覧カードに示し、期限超過でも利用状態は変更しない。過去の言語や時間制情報は推測しない。極短・0分の利用も履歴アイコンと件数を持つ44pxの操作から選べ、部分取得の件数はn+で示す。時間軸は10–300%を10%刻みのBase UI Sliderで拡縮し、中央の時刻を保つ。Macの⌘、その他のCtrl＋時間軸内ホイールではカーソルの時刻を保ち、通常スクロールはそのまま使える。ズームは1操作を1履歴へまとめ、検索・並べ替え・表示形式・日付とともにURLへ保持し、利用詳細や戻る・進むでも復元する。旧compact/overview/normal/detailedの倍率URLは数値へ読み替える。タイムライン全体に最大高さを設けず、卓の数だけ自然に伸ばす。終了済み利用は取得済みの履歴情報だけを示す。
- 統計は期間操作とタブを読込境界の外へ置く。タブ本文の遅延読込と集計取得は同じ集計構造のスケルトンで示す。来店の注文タブも本文内にSuspenseを置き、他タブや見出しを消さない。取得失敗は0件に置き換えず、再取得中は取得済み結果を保つ。
- サイドバーの各グループは初回にすべて展開し、利用者が明示変更した状態を優先する。縮小時は左右余白を均等にし、リンクはhoverとfocusでTooltipに名前を出す。アカウントの操作にはユーザーアイコンを使う。ユーザーセレクタの名前・メールは一行省略し、メニュー内では全文を確認できる。
- ページ見出しは一行でも48pxの領域を確保し、複数行は自然に伸ばす。設定ヘッダーは版と状態のまとまり、操作のまとまりを分け、ラベルの途中で折り返さない。

### ページと選択位置の遷移

ページ本文はRouterの公開View Transition APIで描画snapshotを遷移し、Outletにmotion用のkeyを付けない。初回SSR・同じpathnameの検索条件変更・接続済み客画面を出入りする遷移は対象外。型付きView Transitionの未対応ブラウザーはonResolvedで既存本文だけをMotionで200ms入場させ、nativeとの二重再生を避ける。戻る操作で方向を反転し、shellのナビとスクロールは既存Routerが所有する。Tabsはscope付きLayoutGroup/layoutIdで選択位置を結び、sidebarの選択線は現在の項目内に固定し、客カートはAnimatePresence/popLayoutで追加・削除の位置関係を示す。退場中の行は即時inertにし、入力DOMと明示注文確定を維持する。reduced motionでは移動を止める。

ログインはGoogle、Fingerprintアイコン付きパスキー、区切り線、メールの順に並べる。パスキーを説明枠で囲まず、メールリンク送信は白いoutlineボタンとする。成功した前回の方法にラベルを付ける。新規登録時はブランドと言語切替を持つ任意の登録画面へ案内し、あとで設定でも元の招待・操作へ進める。未登録の認証済みユーザーには閉じられる登録ポップアップを表示し、後回しにしたブラウザーではユーザー単位で7日間再表示しない。未登録を理由に機能を制限しない。

店舗の正方形ロゴは`branding.logo`、ヘッダー用の横長バナーは`branding.banner`へ別々に登録する。バナーは4:1を含む任意の比率を保って全体を表示し、バナー・店名・卓名は同じ横一列に置き、画面幅による縦積みをしない。商品一覧カードは外側24px・内側余白12px・写真12px、カゴは外側24px・内側余白16px・写真8px、Dialogは外側24px・ヘッダー余白16px・画像と閉じる操作8pxの角丸を基本とする。カスタマイズは幅に応じた2列のグループと44px以上のコンパクトな選択行で、一度に見渡せる選択肢を増やす。

## ドキュメント

表示名は日本語でドキュメント、英語でDocumentationとする。ドキュメントは認証必須routeへ置かず、既存の`/help/ja`・`/help/en`を未ログインでも読める公開ページとする。緑色の本アイコンを持つ章一覧はドキュメントのサイドバーへ置き、認証必須側の業務ナビゲーションには章グループを置かない。ログイン後のサイドバー下部にドキュメントリンクを置き、現在の表示言語の目次を別タブで開く。縮小時も本アイコン・Tooltipから利用できる。アプリ側の検索からもドキュメントへ移動できる。Fumadocsの目次・ページ間リンクと共通LanguageSwitchを使う。公開本文は店舗の使い方に絞り、cloneや開発サーバーを導入条件にしない。Markdown・agent索引もログイン不要で、店舗データへの権限とは分ける。

公開ドキュメントの章一覧も管理サイドバーと同じ`NavigationGroup`・`NavigationLink`で表示する。緑色のアイコン付き見出し、文字・余白・罫線、開閉と選択中の表示を揃え、全6章へのリンクを残す。複数行のリンクは上下の余白を保って高さを伸ばし、選択線は項目内で上下に余白を持たせる。項目間を移動する選択線のアニメーションは使わない。Fumadocsがデスクトップのサイドバーとモバイルの目次を所有し、モバイルでは章の選択後に目次を閉じる。公開側のグループ開閉に店舗情報や認証の取得は必要ない。

サイドバーの検索バーは表示と操作名を日本語の検索・英語のSearchだけにし、対象名は入力欄へ並べない。参考UIの入力欄・クリア・結果ポップオーバーを採用し、`Mod+K`で入力へ移る。アプリのページ名・routeと現在の表示言語のドキュメント本文を検索し、候補はサイドバーと同じアイコン・分類色を使う。店舗内ページは選択中の店舗へ遷移し、管理者限定ページは既知の権限に合わせる。公開ドキュメントでは認証・店舗情報を読み込まず、店舗が必要な候補は既存の認証後にアクセス可能な店舗へ解決する。ドキュメント検索の読込中・0件・失敗を区別し、失敗してもページ候補と入力を保ち再試行できる。検索結果の選択でモバイルのサイドバーを閉じる。

公開ドキュメントと管理画面は共通AppHeader・LanguageSwitch・PageHeaderを使う。サイドバーの開閉ボタンは共通NavigationToggleを使い、ページ上部のAppHeaderだけへ置く。サイドバー内や折りたたみ後の浮遊ボタンは置かない。デスクトップは同じ本体幅・アイコン列の縮小表示、モバイルは共通NavigationDrawerで左から開き、同じ閉じる操作・Escape・フォーカス復帰を使う。Mod+Bはデスクトップだけで一度登録し、入力中には動作させない。公開側もFumadocsの公開slotとページツリーを使い、標準シェルから追加のボタンや右側drawerを生成しない。ドキュメントの言語はURLを正本とし、切替時は同じ章へ移り、認証や店舗情報は取得しない。検索入力のEnterは先頭、Cmd/Ctrl+1〜4は分類を通した表示順の先頭4件を開く。IME変換中・Safariの変換確定・古い候補では遷移しない。候補のインラインMarkdownと表のセルを読みやすく描画し、内側のリンクや埋込は作らない。日本語tokenizerと英語stemmingを索引・検索語・一致部分の強調で共有する。

公開ドキュメントのページ面は管理画面と共通の`page-layout`で角丸・背景・影・外側の余白・本文幅と余白を揃える。PageHeaderはページ幅を使い、ページ内TOCは本文領域へ置く。モバイルのTOCも本文内で開閉する。アプリを開く導線は共通SidebarFooter・NavigationLinkを使い、サイドバー下部へ配置する。

本文はplugin同梱の参照資料をそのまま表示し、公開ドキュメント・ログイン不要・Markdown・Agent向け索引などの配信形式や実装上の案内を付加しない。

音声の応答待ちは実イベントから確認中・検索中・画像読取中を区別し、spinnerを表示する。公開された推論要約とツールの処理状態・説明は、展開操作を求めず常時表示する。推論要約のMarkdownはStreamdownで描画し、長い内容だけスクロールできる。出典はリンクで参照できる。参考カードにはタイトル・ドメイン・説明・OGP画像と中央favicon付きQRを置き、画像失敗時もタイトルとQRを残す。参考カードは既定240px・最小224pxの会話ペインへ収まる幅と余白にし、QRは144pxの縮小表示からタップで拡大できる。長いURLは拡大表示で読み取りを確認する。追従中の追従操作は隠し、非追従時だけ色付きの最新会話へ戻る操作を表示する。カメラはフレームの取得成功時だけシャッター効果を出し、OFF・失敗時は出さない。ハイライトとspinnerはreduced motionでは静止表示にし、シャッターの点滅を止める。

## 店員への用件相談と呼び出し履歴

右上の呼び出しボタンは、ボタンを指す矢印付きの非モーダルPopoverを開く。背景overlay・スクロールロック・フォーカストラップを設けず、開いたまま会話やメニューを操作できる。背景操作では閉じず、閉じるボタン・再押下・Escapeで閉じ、起点へフォーカスを戻す。画面内に収め、本文だけをスクロールする。下部には赤い塗りつぶしのすぐに店員を呼ぶボタンを残す。英語はCall staff immediatelyとする。

初期表示は音声の状態・短い字幕と直近1件の呼び出しに絞り、日時・用件・状態を追加操作なしで確認できる。全履歴と引き継ぎメモの詳細は明示的に開く。用件選択と履歴の詳細は明示的なボタンで吹き出し内の別画面へ移動する。accordionやdetailsによる折りたたみは使わない。案内本文は用件が分かってから表示する。Helpのような曖昧な切り替えは置かない。用件相談は既存音声接続を共有し、未接続なら開いた時点で開始する。接続中・接続処理中の会話を作り直さず、現在の会話へ用件相談を渡す。今回開始した音声は明示的に閉じる際に停止する。既存の会話と商品詳細へ移った会話は維持し、履歴の閲覧・追加読込では接続しない。マイク拒否・音声未設定でも用件ボタン・案内・呼び出しを利用できる。

店舗案内は管理画面の日英設定と関連商品・HTTPSリンクを使う。お冷・食器回収・食器追加などが商品なら、価格・販売状態を表示して通常の商品詳細・カート・明示承認へ進む。表示だけで手配済みにしない。未登録情報は推測しない。

店側はフロアの最上部に呼び出し中の卓を古い順で並べ、既存の白いカードと薄いグレーの見出しを使い、黄色は呼出中のラベル・アイコン・件数に限定する。対応済みにするボタンは緑の面・枠・文字で示す。検索・卓の絞り込み・表示形式に関係なく、日本語メモ・客の原文・案内済み内容・未解決点の全文と対応済みボタンを表示する。卓詳細でも同じパネルをタブより上に置く。原文や経緯をaccordionや別画面へ隠さない。メモのない既存の呼び出しは用件未確認とし、日時や内容を推測しない。呼出・対応済み・詳細上部の来店開始は日英の相対時刻で表示し、正確な日時はtime要素とtitleに保持する。表示中も経過を更新する。

呼び出し履歴は現在の来店だけを新しい順でページ送りする。日時・日本語の引き継ぎ要約・呼出中／対応済みを表示し、詳細で依頼の原文と言語、案内済み内容、未解決点、対応済み日時を確認できる。店員の対応済み通知で更新し、会話ログの件数や再読込で消さない。次の利用客に前の来店の履歴を表示しない。吹き出しや音声の終了は対応済み操作にしない。

用件相談の商品自動候補は、登録された名称・読み・別名の完全一致に限定する。説明文の水という語や部分一致だけで酒類等を候補に混ぜない。名称が異なる商品は店舗案内の関連商品として明示する。
